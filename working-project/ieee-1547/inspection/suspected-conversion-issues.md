## 검사 범위와 해석

JSON의 내용만 사용해 참조 구조, 부모–자식 관계, 출처 좌표, 제목 계층, 목록, 표 셀 범위, 수식과 주변 설명, 단락 및 주석 연결을 검사했다. 원본 PDF, 외부 이미지, 웹 자료, 외부 라이브러리는 사용하지 않았다. 원본 JSON은 수정하지 않았다.

아래 페이지 번호는 인쇄된 쪽수가 아니라 JSON의 `prov.page_no`다. `#/texts/1040`과 같은 위치는 JSON 내부 참조 경로다. 후보 수는 해당 판별 기준에 걸린 항목 수이며, 확정된 변환 오류 수를 의미하지 않는다.

공식 DoclingDocument 스키마 검증과 공식 HTML 변환은 수행하지 않았다. 내부 구조 충돌을 확인했더라도, 이를 공식 스키마 위반으로 단정하지 않는다. PDF와 대조하지 않았으므로 원본의 정확한 표현이나 누락 여부는 확정할 수 없다.

## 정상으로 확인한 부분 및 오탐 방지

- JSON 파싱에 성공했다.
- 검사한 `$ref`와 `self_ref`에서 끊어진 참조 또는 경로 불일치를 찾지 못했다.
- `children`을 기준으로 검사한 부모–자식 연결에서 불일치, 중복 소속, 순환, 도달 불가능 노드를 찾지 못했다.
- 검사한 `prov`에서 존재하지 않는 페이지 참조, 방향이 뒤집힌 좌표, 허용 오차 1포인트를 넘어 페이지 밖으로 나간 좌표를 찾지 못했다. 표 셀 자체의 모든 좌표를 검사했다는 뜻은 아니다.
- 트리 순회 시 항목의 첫 번째 출처 페이지 번호가 이전 항목보다 작아지는 사례는 없었다. 이것만으로 같은 페이지 안의 읽기 순서가 올바르다고 판단하지 않는다.
- 일부 목록 항목에서 `orig`의 번호가 `text`에서 제거됐지만 `marker`에 보존돼 있다. 예를 들어 `#/texts/429`의 `a)`는 `marker`에 남아 있다. 이를 텍스트 유실로 판정하지 않았다.
- `charspan` 끝값이 `text` 길이보다 큰 출처 47건은 `orig` 길이 안에 있었다. 목록 표시 제거 등 정규화 전후 길이 차이만으로 오류를 판정하지 않았다.
- 셀 범위로 덮이지 않는 위치가 있는 표 17개는 빈칸일 수 있으므로, 그 사실만으로 내용 누락으로 판정하지 않았다.
