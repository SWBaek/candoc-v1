# DoclingDocument 검사·교정 기본 규칙 v0.1

- 버전: v0.1
- 작성일: 2026-10-06
- 적용 대상: 디지털 PDF에서 변환한 DoclingDocument의 구조적·의미적 오류 검사와 교정

## 1. 목적과 검사 범위

문서 전체의 영역과 구조부터 개별 요소의 내부 구조와 내용까지 검토한다. 탐지 순서와 교정 확정 순서를 구분하며, 판단 사이의 의존 관계에 따라 교정을 진행한다.

기본 검사는 대상 JSON의 내부 근거를 사용한다. `orig`, `text`, 출처 페이지와 좌표, 참조 관계, 주변 정의와 설명 등을 대조한다. 내용의 의미 검사는 변환 결과가 이러한 내부 근거와 일치하는지 확인하는 작업이다. 원문의 기술적 주장이 옳은지를 심사하지 않는다.

JSON만으로 판단할 수 없는 원래 표현이나 누락 여부는 미확정으로 남긴다. 외부 자료나 원본 PDF를 통한 추가 검증은 수행 여부와 사용 근거를 구분해 기록한다.

## 2. 원본과 근거 보존

- 입력 원본 DoclingDocument는 수정하지 않는다. 모든 교정은 사본에서 수행한다.
- 페이지 제외는 원본을 보존한 채 포함·제외 결정과 근거를 기록하고, 교정된 사본에 반영한다. 제외 결정을 취소할 수 있도록 원본 페이지와의 연결을 유지한다.
- 의심 항목과 확정된 오류를 구분한다. 탐지 조건에 걸린 후보 수를 확정 오류 수로 표현하지 않는다.
- 교정은 근거가 충분한 범위에서 확정한다. 내부 불일치가 발견됐다는 사실만으로 원래의 정확한 내용을 추정해 채우지 않는다.
- 기존 JSON의 라벨, 제목 수준, 부모·자식 관계도 검사 대상이다. 저장된 분류를 그대로 정답으로 취급하지 않는다.
- `orig`, `text`, 목록의 `marker` 등 표현 차이를 함께 확인한다. 정규화에 따른 차이만으로 내용 유실을 판정하지 않는다.

## 3. 탐지와 교정 확정 원칙

### 독립적인 탐지는 함께 수행한다

표 셀 충돌, 수식과 변수 정의의 불일치, 참조 이상처럼 다른 검토의 완료를 기다릴 필요가 없는 검사는 처음부터 독립적으로 수행하고 결과를 기록한다.

탐지된 항목 중 다른 판단에 영향을 받는 부분만 확정을 보류한다. 앞 단계의 미확정 항목 하나 때문에 문서 전체의 검토를 멈추지 않는다.

### 교정은 의존 관계에 따라 확정한다

아래 전체 검수 절차의 단계 번호는 검토 범위와 교정 확정의 의존 관계를 나타낸다. 문서 전체에서 한 단계를 모두 끝내야 다음 단계로 넘어가는 고정 실행 순서가 아니다.

다른 판단에 의존하지 않고 근거가 충분한 교정은 먼저 확정할 수 있다. 실제 우선순위는 항목별 근거의 확실성, 영향 범위, 의존 관계를 확인해 정한다.

### 변경 영향을 받는 항목만 재검토한다

읽기 순서, 제목, 요소의 소속, 단락 경계는 서로 영향을 줄 수 있다. 앞선 판단이 바뀌면 그 판단에 의존하는 결과를 다시 검사한다.

예를 들어 페이지 포함·제외 결정이 바뀌면 해당 페이지와 앞뒤의 문단·표·각주 연결 및 제목 구조를, 캡션 소속이 바뀌면 해당 그림과 주변 문단을, 반복 머리말 분류가 바뀌면 관련 제목과 페이지 연결을 다시 확인한다. 영향이 연결된 다른 절이나 참조가 있으면 재검토 범위를 넓힌다. 관련 없는 항목까지 매번 처음부터 검사하지 않는다.

## 4. 전체 검수 절차

기본 검토 흐름은 대상·기본 무결성 확인 → 페이지 선별 → 영역·역할 구분 → 읽기 순서·제목·소속 검토 → 단락·복합 요소 검토 → 내부 일관성·전체 교차 확인 → 결과 판정과 기록이다.

페이지 선별은 입력 문서의 모든 페이지를 대상으로 한다. 이후에는 유지할 페이지와 요소 전체를 검사하며, 기존 의심 목록에 있는 항목만으로 범위를 제한하지 않는다. 제외가 확정된 페이지는 제외 근거와 세부 검수를 수행하지 않은 범위를 기록한다. 제외 여부가 미확정인 페이지는 보류 대상으로 남기고 독립적인 검사는 계속한다. 판단이 바뀌면 영향을 받는 항목만 다시 검사한다.

### 0. 대상과 범위 확인

- 검사 대상: 입력 문서와 기존 검사 결과.
- 검사 내용: 검사할 JSON을 특정하고 원본 보존을 확인한다. 기존 검사 이후 파일이 바뀌었는지 확인하며, JSON만으로 검사할 범위와 추가 확인이 필요한 범위를 구분한다.
- 판단 기준: 같은 입력과 범위에서 수행한 검사 결과는 재사용할 수 있다. 입력이 바뀌었으면 변경 영향을 받는 검사 결과의 유효성을 다시 확인한다.

### 1. 기본 무결성

- 검사 대상: JSON과 참조 구조.
- 검사 내용: 파싱, 참조 경로, 부모·자식 연결, 중복 소속, 순환, 도달 불가능 요소, 출처 페이지와 좌표를 검사한다.
- 판단 기준: 무결성 검사 통과를 의미적 정확성이나 공식 스키마 검증 통과로 간주하지 않는다. 문제가 있는 정보에 의존하는 판단은 보류하고 독립적인 검사는 계속한다. 같은 파일에서 이미 수행한 검사는 결과를 재사용한다.

### 2. 페이지 선별과 제외

- 검사 대상: 입력 문서의 모든 페이지와 페이지 간 연결.
- 검사 내용: 문서에 포함할 페이지를 정한다. 빈 페이지, 중복 페이지, 변환 과정에서 들어온 부가 페이지 등을 제외 후보로 확인한다. 표지·목차·서문의 역할과 검수 목적을 확인하고 포함 여부를 결정한다. 제공된 원문 페이지 이미지가 있으면 대조에 사용할 수 있으며, 사용한 근거를 기록한다. 제외 대상은 먼저 표시하고 확정한 뒤 교정된 사본에 반영한다.
- 판단 기준: 텍스트가 없다는 사실만으로 빈 페이지라고 판단하거나, 표지·목차·서문이라는 이유만으로 자동 제외하지 않는다. 페이지 전체의 제외와 머리말 등 개별 요소의 보정을 구분한다. 원본 페이지 번호를 추적할 수 있게 보존하고, 제외를 사본에 반영할 때 앞뒤로 이어지는 문단·표·각주와 참조·소속·출처 구조를 확인한다. 제외 결정이 바뀌면 영향을 받는 검사 범위를 다시 검토한다.

### 3. 영역·큰 역할·소속

- 검사 대상: 페이지 전체와 주요 내용 영역.
- 검사 내용: 반복 머리말·꼬리말, 페이지 번호, 본문, 각주 영역을 구분한다. 표·그림 내부 텍스트, 목록, 캡션, 수식 등의 큰 역할과 소속을 잠정 판단한다.
- 판단 기준: 반복 문구와 위치를 함께 살피며 표지나 본문 시작의 실제 문서 제목을 반복 머리말과 구별한다. 각주 등 내용이 있는 요소는 보존한다. 기존 라벨과 소속을 정답으로 취급하지 않으며, 불확실한 역할과 소속은 잠정 판단으로 남긴다.

### 4. 읽기 순서와 페이지 연결

- 검사 대상: 영역 안의 요소 순서와 여러 페이지에 걸친 내용.
- 검사 내용: 다단 배치, 같은 페이지 안의 읽기 순서, 페이지를 넘어 이어지는 내용을 검사한다. 본문과 각주·머리말 등 서로 다른 영역이 잘못 합쳐졌는지 확인한다.
- 판단 기준: 영역과 큰 소속을 근거로 순서를 판단한다. 페이지 번호가 순서대로라는 사실만으로 읽기 순서가 올바르다고 판단하지 않는다. 제목·목록·표 구조나 요소 소속이 바뀌면 관련 순서와 연결을 다시 확인한다.

### 5. 제목과 문서 개요

- 검사 대상: 제목 후보 전체와 문서의 개요.
- 검사 내용: 제목 여부를 먼저 확인하고, 수준, 절 번호, 상하 관계, 누락 또는 중복 후보를 검사한다. 표지, 목차, 본문, 부속서, 참고문헌의 구분도 확인한다.
- 판단 기준: 절 번호의 깊이는 근거로 활용하되, 번호 깊이만 보고 제목 수준을 일괄 결정하지 않는다. 반복 머리말이나 목록 항목이 제목으로 남아 있는지 확인한 뒤 수준을 판단한다.

### 6. 요소 관계의 정밀 검토

- 검사 대상: 캡션, 주석, 각주, 본문 참조와 관련 요소.
- 검사 내용: 캡션이 올바른 표·그림에 연결됐는지, 주석과 각주가 어디에 속하는지 확인한다. 다른 영역에 잘못 소속됐거나 독립적으로 남은 요소를 검사한다.
- 판단 기준: 참조 경로가 유효한지와 내용상 연결이 올바른지를 구분한다. 연결이 없거나 가깝게 배치됐다는 사실만으로 소속을 확정하지 않는다. 관계 판단이 읽기 순서나 제목 판단을 바꾸면 관련 항목을 다시 확인한다.

### 7. 단락과 문장 경계

- 검사 대상: 본문·주석 등 역할과 소속이 확인된 텍스트.
- 검사 내용: 한 문단의 불필요한 분리, 여러 문단의 잘못된 병합, 줄바꿈·공백·줄 끝 하이픈, 페이지 경계의 문장 연결을 검사한다.
- 판단 기준: 역할과 소속을 확인한 뒤 문단 병합을 판단한다. 인접한 텍스트라는 이유만으로 합치지 않으며, 줄바꿈이나 하이픈이라는 이유만으로 제거하지 않는다. 문장 관계와 출처 정보를 함께 사용한다.

### 8. 목록 내부 구조

- 검사 대상: 목록과 항목 전체.
- 검사 내용: 목록 여부, 항목 표시, 번호 순서, 들여쓰기, 중첩 관계, 항목 간 조건 관계를 검사한다. 목록이 제목이나 일반 문단으로 분류됐는지도 확인한다.
- 판단 기준: 번호, 좌표, 문장 관계를 함께 사용한다. 항목 표시가 `marker`에 보존됐는지 확인한다. 목록 내부 구조 판단이 문단 경계나 제목 판단에 영향을 주면 관련 항목을 다시 검사한다.

### 9. 표·그림 내부 구조

- 검사 대상: 표와 그림 전체.
- 검사 내용: 표의 행·열·헤더·셀 범위·병합·충돌을 검사한다. 그림 내부 텍스트의 소속과 일반 본문으로의 혼입을 확인한다.
- 판단 기준: 표의 빈칸이라는 사실만으로 누락을 판정하지 않는다. 그림 내부의 짧은 텍스트 조각을 일반 본문의 문단 분리 기준만으로 오류라고 판단하지 않는다. 그림의 연결선과 도형 등 시각적 관계는 JSON으로 판단 가능한 범위를 명시한다.

### 10. 표현과 내부 의미 일관성

- 검사 대상: 텍스트, 수식, 기호, 단위.
- 검사 내용: `orig`, `text`, `marker`, 주변 설명을 대조한다. 변수·첨자·등호·단위·특수문자 손상과 내부 설명의 불일치를 검사한다.
- 판단 기준: 독립적으로 확인할 수 있는 항목은 처음부터 탐지한다. 구조 교정으로 문맥이나 소속이 달라지면 다시 확인한다. 내부 불일치를 확인할 수 있어도 정확한 교정 내용을 결정할 수 없으면 추가 확인이 필요한 항목으로 남긴다. 원문의 기술적 주장 자체를 평가하지 않는다.

### 11. 문서 전체의 교차 확인

- 검사 대상: 앞 단계의 결과와 문서 내 참조.
- 검사 내용: 제목 계층과 내용 소속, 절·표·그림·수식 참조, 번호 체계의 일관성을 다시 확인한다. 앞 단계의 판단 사이에 충돌이 있는지 확인한다.
- 판단 기준: 번호가 비었다는 이유만으로 누락을 확정하지 않는다. 판단 충돌이 발견되면 근거와 의존 관계를 확인하고 영향을 받는 범위를 재검토한다.

### 12. 결과 판정과 기록

- 검사 대상: 모든 검사 범위와 발견 항목.
- 검사 내용: 정상, 오류 확인, 의심, 판단 불가를 구분한다. 각 항목의 근거와 교정 가능 여부, 추가 확인 사항을 기록하고 검사하지 못한 범위를 남긴다.
- 판단 기준: 오류 발견과 교정 가능 여부를 구분한다. 대표 사례나 기존 의심 항목만 확인했다면 부분 검수로 기록한다. 기록은 아래 검사 기록 원칙을 따른다.

## 5. 검사 기록

공통 규칙은 이 문서에 두고, 개별 문서의 검사 결과는 `working-project/<문서>/inspection`에 기록한다.

항목에는 위치, 근거, 판단, 필요한 후속 확인을 남긴다. 한 항목이 여러 단계에 걸쳐 있으면 기존 식별자를 유지하고 검토 단계별 판단을 구분한다. 검토 과정에서 의심이 해소되면 그 근거도 기록한다.

페이지 선별 결과에는 원본 페이지 번호, 포함·제외·보류 상태, 제외 사유와 판단 근거를 남긴다. 제외가 확정된 범위와 아직 검사하지 않은 범위를 구분하며, 포함·제외 결정이 바뀌면 관련 검수 결과를 재검토 대상으로 표시한다.

검사하지 않은 사항과 JSON만으로 판단할 수 없는 사항을 명시한다. 기록 형식이나 별도 파일 묶음을 필수 출력으로 추가하지 않는다.

## 6. 완료 조건

### 전체 검수 완료

모든 입력 페이지의 포함·제외 결정을 확인하고, 유지할 페이지와 모든 요소 유형의 검사 범위, 제외 사유, 발견 항목의 판단과 미확인 사항을 기록한 상태를 전체 검수 완료로 판단한다.

JSON만으로 판단할 수 없는 사항은 판단 불가와 그 이유를 남긴다. 포함·제외 결정을 확정하지 못한 페이지가 있거나, 유지할 페이지에서 검사할 수 있는 범위를 일부만 확인했다면 전체 검수 완료로 기록하지 않는다. 검수 완료는 오류가 없거나 발견한 오류의 교정까지 끝났다는 뜻이 아니다.

### 교정 완료

교정은 근거와 의존 관계에 따라 사본에서 확정하며, 완료 여부는 다음 조건을 모두 수행해 확인한다.

- 변경 영향을 받는 구조와 내용을 재검토한다.
- 교정된 사본이 표준 DoclingDocument 스키마에 따라 유효한지 검증한다.
- Docling 공식 HTML 변환 함수로 실제 변환해 오류가 없는지 확인하고, 변경한 구조와 내용이 변환 결과에 올바르게 반영됐는지 확인한다.

스키마와 HTML 변환의 성공만으로 원본 PDF와의 의미적 일치가 입증됐다고 판단하지 않는다. 미확정 항목은 완료된 교정과 구분해 남기며, 수행하지 않은 검증을 통과했다고 기록하지 않는다.
