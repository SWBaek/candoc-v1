# 3단계 영역·큰 역할·소속 구현 계획

## 범위

- 3단계의 첫 화면을 반복 머리말·꼬리말·페이지 번호 후보의 묶음 검수로 바꾼다. 본문·각주·소속의 개별 검토는 보조 경로다.
- 문구 정규화·유사 위치·서로 다른 페이지 출현으로 후보 그룹을 만들며, 페이지 번호는 서로 다른 숫자/로마 숫자도 같은 위치·번호 패턴으로 묶는다. 후보는 자동 확정하지 않는다.
- 대표 사례, 전체 대상 수·원본 페이지 목록, 개별 예외 선택 해제·별도 판단을 제공한다. 실제 선택 대상 수·목록을 확인한 뒤 공통 역할을 명시적으로 저장하거나 초안을 취소한다. 직전 일괄 저장의 이전 판단을 원자적으로 복원하며 후속 변경과 충돌하면 복원을 거부한다.
- 텍스트·표·그림과 그룹을 원본 참조로 식별한다. 그룹의 페이지는 자손 출처에서 유도했다고 표시하며 출처 없는 항목도 별도로 접근한다. 표 셀 내용과 부모·자식, orig/text, content_layer를 대조 근거로 제공한다.
- 좌표 원점을 변환해 선택 요소를 이미지에 표시한다. 좌표가 없거나 유효하지 않으면 추정하지 않고 안내한다. 같은 문구와 비슷한 위치의 반복 출처는 참고 근거이며 확정 오류로 분류하지 않는다.
- 정상·오류 확인·의심·판단 불가, 영역·큰 역할·잠정 소속, 사유·근거·후속 확인을 SQLite에 명시적으로 저장한다. 실제 교정은 하지 않는다.
- 제외 페이지는 기본 검사 범위에서 빼고 미검수·보류 페이지는 계속 검사할 수 있게 표시한다. 여러 페이지 요소는 유지 범위의 어느 페이지라도 포함되면 검사 대상이다.
- 선택·화면 방문은 완료가 아니다. 모든 대상 요소 판단, 페이지 포함·제외 확정, 의심 해소와 전체 범위·근거 메모를 완료 조건으로 검증한다. 판단 불가는 이유를 기록한 경우 검수 결과로 남길 수 있다.
- 초안 저장·취소·이동 확인, 충돌과 재시작 복구를 기존 revision 트랜잭션에 통합한다. 페이지 범위 변경은 해당 요소 판단을 재검토로 표시하며, 역할·소속 변경은 이미 완료한 관련 후속 단계를 재검토로 표시한다.

## 제외

- 4 읽기 순서·페이지 연결과 5 제목·문서 개요 전용 화면은 구현하지 않는다.
- 자동 AI 역할 판정·대화, 원본 삭제·라벨/트리 수정, 교정 사본 출력은 구현하지 않는다. 따라서 공식 스키마·HTML 교정 완료를 주장하지 않는다.
- 기존 검수 판단을 테스트 데이터로 변경하지 않는다. 검증은 임시 DB에서 수행한다.

## 완료 조건과 검증

- 구조·HTTP·저장·완료 조건을 문서화하고 디자인 계약과 README를 갱신한다.
- API에서 반복 후보·변하는 페이지 번호·범위 밖 페이지·그룹 일부 제외·그룹 대상별 기록·모든 원본 prov 보존·일괄 저장/복원의 원자성, 출처 없는 항목·구조 그룹·다중 출처·좌표·잘못된 참조·소속 순환·입력 변경·충돌·완료 제한·재검토·기존 DB 보존을 확인한다.
- 브라우저에서 저장→새로고침→재시작, 초안 취소·이동 확인, 선택/완료 구분, 오류, 제외 범위, 출처 없는 항목, 이미지 위치, 두 테마와 1512/1024/375/320px을 확인한다.
- 타입 검사·빌드·API 검사·브라우저 회귀 검사를 수행하고 결과를 기록한다. 로컬 Git에 구현을 커밋하고 독립 검토 후 다음 지시를 기다린다.

## 구현과 검증 결과

- 반복 머리말·꼬리말·서로 다른 페이지 번호의 후보 묶음을 첫 화면으로 구현했다. 대표 선택, 전체·범위 내·선택 수, 전체 원본 페이지, 대상별 상태와 예외 체크, 명시적 공통 판단 저장·초안 취소·직전 일괄 판단 복원을 제공한다. 본문·각주·표·그림·소속·출처 없는 항목은 개별 검토 경로로 제공한다.
- 원본 모든 prov와 라벨·소속·내용은 변경하지 않는다. 검수 판단과 일괄 복원 정보만 기존 revision 트랜잭션의 별도 SQLite 테이블에 기록한다. 제외 페이지·예외를 저장하지 않고, 오류·충돌 시 전체 저장을 롤백한다.
- `npm run typecheck`, `npm run build` 통과. `npm test` 23/23 통과. 좌표 검사는 임의 반올림 대신 `1e-12` 수치 허용 오차로 확인한다. 원자성 검사의 의도적인 SQL 실패 로그는 실패 주입이며 테스트는 통과했다.
- 최초 브라우저 검사에서 초안 취소 후 개별 검토 전환 직후 이전 dirty 상태가 남는 문제를 발견했다. reset·discard·save 직후 부모 초안 상태를 함께 갱신해 수정했다. 수정 후 3단계 합성 워크플로와 실제 입력 레이아웃 검사를 다시 실행해 모두 통과했다.
- 합성 브라우저 검사는 범위 밖 대상·개별 예외, 선택한 대상만 저장, 이전 개별 판단 복원, 초안 취소·이동 확인, 출처 없는 항목과 표 대조, 실제 revision 충돌 시 초안 보존, 저장·복원·새로고침·재시작 복구를 확인했다.
- 실제 입력의 전체 3,110요소는 격리 DB에서 확인했다. 1512/1024/375/320px, 밝은/어두운 테마, 주요 텍스트 4.5:1 이상 대비·12px 이상 크기, 터치 대상 44px 이상, 가로 넘침 없음과 자동 판단·완료 없음이 통과했다. 생성된 데스크톱·모바일 스크린샷을 시각 확인했다.
- 독립 리뷰 보고: `npm test` 23/23과 `npm run test:browser` 전체 회귀 통과. 별도 임시 DB의 실제 Edge에서 페이지 번호 후보 88개 중 예외 1개 해제 → 87개 명시적 저장 → 새로고침 복구 → 직전 복원으로 0개, 완료 제한을 직접 확인했다. CUA 캡처는 시간 초과였으며 테스트의 `roles-light-1512/375.png`를 시각 확인했다. 이 Edge 확인은 독립 리뷰 제공 결과와 자체 자동 검사 결과를 구분해 기록한다.
- 기존 실행 서버를 새 백엔드로 재시작했다. 테스트 판단은 저장하지 않았다. 재시작 전후 기존 API 필드 전체가 일치하고 실제 revision 47·기존 페이지 판단·단계 기록을 유지했다. 새 역할 판단은 0개, 기존 16개 제외 페이지를 반영한 영역 검사 범위는 2,953요소다.
- 원본 JSON SHA-256은 `bc2986e0685472527debf1c85129a17041501f8441270c0e69069732ca91ccff`로 동일하다. 원본 JSON·PNG 167개를 삭제하지 않았다.
- 디자인 계약 v0.5, 3단계 HTTP·저장 계약, README와 외부 fixture 설정을 갱신했다. 4·5단계 전용 구현은 시작하지 않았다.

## 한정사항과 Git 기록

- 반복 탐지는 고정 위치·문구·번호 패턴의 후보 생성이며 누락·오묶음이 가능하다. 사용자가 전체 대상과 예외를 검토하고 명시적으로 판단한다. 실제 모델 호출은 수행하지 않았다.
- 역할·소속은 잠정 검수 기록이다. 원본 교정·사본 출력·공식 Docling 스키마/HTML 교정 완료 검증은 수행하지 않았다. 실제 입력 레이아웃 검사는 의미적 판정 정답의 증거가 아니다.
- 로컬 기준 커밋 `c83f2f5`를 유지하고 `05fa159`에서 원본 fixture의 현재 추적만 해제했다. Git 이력을 재작성하지 않았으므로 원본 입력은 기준 커밋 이력에 남아 있다. 로컬 원본 파일은 보존하고 앞으로 Git에서 제외한다. 자세한 경로는 [로컬 재현 입력](../local-fixtures.md)을 따른다.

## 기존 사용자 서버 재시작에 대한 읽기 전용 확인

이번 구현 중 기존 사용자 서버를 재시작한 것은 승인된 운영 경계 위반이다. 추가 중단·재시작으로 되돌리지 않았다. 앞으로는 기존 서버를 제어하지 않고 독립 임시 DB·별도 포트에서만 테스트한다. 이 경계를 AGENTS.md와 README에 반영했다.

- 현재 `http://127.0.0.1:4380`은 응답하며 확인 시 수신 프로세스는 PID 34092, `node.exe server/main.mjs`다. 현재 화면은 페이지 선별(activeStage 2)이다.
- 재시작 직전 보관한 `/api/review` 응답과 재시작 후 기존 필드 전부를 deepEqual로 비교했다. revision 47, 포함 122·제외 16·미검수/보류 0, 선택·필터·표시 설정·메모·근거·시각·사용자 단계·재검토 기록이 일치했다. 기존 API에 노출되지 않는 과거 0·1단계의 사전 DB 덤프는 없으므로 이 두 행의 전후 직접 비교는 수행하지 않았다.
- 직전 추천 API 상태는 `idle`이었다. 이후에도 `id: null`, `status: idle`, `suggestions: []`, `error: null`이다. 실행 중 추천이나 완료 결과가 있었던 상태가 아니므로 확인한 직전 상태에서 추천 결과 손실은 없다. 서버 재시작은 메모리 추천을 초기화하는 동작이다.
- 새 백엔드는 `role_reviews`와 `role_batches`에 `CREATE TABLE IF NOT EXISTS`를 실행했다. 현재 두 테이블이 실제 DB에 존재하고 각 0행이다. 기존 테이블의 ALTER/DROP·역할 판단/일괄 기록 INSERT는 이 재시작에서 수행하지 않았다. 재시작 전 schema 덤프를 수집하지 않아 두 테이블의 사전 존재 여부를 직접 비교한 증거는 없으며, 이전 백엔드 코드에는 이 두 테이블 생성 경로가 없다.
- 읽기 전용 DB 연결로 현재 테이블 행 수를 확인했다: reviews 1, page_decisions 138, stage_reviews 13(기존 0·1 포함), review_impacts 0, role_reviews 0, role_batches 0. 실제 DB에 테스트 판단·완료를 저장하지 않았다.
- 원본 JSON SHA-256이 기존 값과 동일하며 PNG 167개의 바이트를 기준 커밋 blob과 비교해 모두 일치했다. 확인 상세는 Git에서 제외한 `web-ui/qa/stage3-live-readonly-audit.json`에 기록했다.
