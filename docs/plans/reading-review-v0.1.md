# 4단계 읽기 순서와 페이지 연결 구현 계획

## 범위

- 페이지·잠정 영역별 원본 트리 순서와 원문 위치/소속을 함께 보며 전체 출처 occurrence의 순서안을 검토한다. 서로 다른 단/소속도 같은 영역 안에서 함께 이동할 수 있으며 다단 순서를 좌표만으로 자동 확정하지 않는다.
- 인접 유지 페이지의 경계를 양쪽 원문·전체 요소로 대조한다. 제외 페이지를 건너뛴 경우 원본 번호와 제외 목록을 표시한다. 여러 문단·표·각주 연결과 명시적인 연결 없음 판단을 기록한다.
- 선택·이동·순서 변경·연결 편집은 초안이다. 명시적 저장·초안 취소·원본 순서로 초안 복원과 이동 확인, revision 충돌·재시작 복구를 지원한다.
- 원본 JSON·라벨·트리·텍스트·모든 prov를 보존한다. 역할·소속 판정과 페이지 범위가 바뀌면 관련 순서·경계를 재검토로 표시한다.
- 출처/원본 트리 순서가 없는 항목, 역할·소속 미확정은 숨기지 않는다. 독립적인 의심·판단 불가 기록은 가능하며 확정 순서·연결과 완료는 필요한 근거·범위 확인을 요구한다.
- 순환·중복·없는 참조·도달 불가를 경로와 영향 대상으로 진단한다. 영향 대상의 정상 확정을 제한하며 미확정 순서의 표시 목록과 알려진 원본 순서를 구분한다. 루트와 연결되지 않은 순환에도 순서 인덱스를 부여하지 않는다.
- 전체 유지 범위의 순서와 페이지 경계 판단, 페이지·영역 판단과 미검수·재검토·의심 및 범위 메모를 UI/API에서 완료 조건으로 확인한다.

## 제외와 운영 경계

- 5단계 제목·문서 개요 전용 구현, 실제 모델 호출, 자동 교정·사본 출력·공식 스키마/HTML 교정 완료 검증은 수행하지 않는다.
- 기존 사용자 서버와 실제 DB는 제어·변경하지 않는다. 테스트와 미리보기는 임시 DB·별도 포트만 사용한다. 원본은 읽기 전용이며 Git에서 제외한다.

## 검증

- API: 다단 순열·누락/중복/범위 밖 거부, 다중 prov·원본 트리와 출처 없는 항목, 제외 간격·다중 연결·타입/영역 혼입·원자성, 의존 판단 변경·복구·충돌·완료 제한.
- 브라우저: 원문/순서 대조·위/아래 이동·저장·취소·원본 초안 복원, 양쪽 경계·명시적 연결 없음/다중 연결, 초안 이동 확인·실패·새로고침·재시작, 밝은/어두운 테마·1512/1024/375/320px·터치·키보드.
- 타입 검사·빌드·전체 API/브라우저 회귀, 원본 및 기존 사용자 기록 읽기 전용 비교, 계약·README·디자인 계약 갱신 후 로컬 커밋과 보고.

## 최종 구현과 검증 결과

- `server/reading-review.mjs`의 트리 진단·영역/경계 생성·원자적 기록·의존 지문과 `ReadingReview` UI를 기존 revision/초안 이동 확인 흐름에 연결했다. 임시 SQLite에는 `order_reviews`/`boundary_reviews`만 추가하고 실제 사용자 DB에는 적용하지 않았다.
- 타입 검사·격리 빌드 통과. 전체 `npm test` **32/32** 통과(기존 23개 + 4단계 9개). 순환/중복/없는 참조/도달 불가, 출처 전체 보존, 다중 연결·잘못된 대상·정상 제한, 트랜잭션 중간 실패, 역할 일괄 복원과 범위 변경, 완료 제한을 검증했다.
- 전체 `npm run test:browser` 회귀 통과. 기존 페이지 선별/AI 패널/3단계와 새 4단계 합성 워크플로·실제 입력 레이아웃을 확인했다. 실제 별도 자식 프로세스의 PID가 바뀐 뒤 SQLite 저장 상태가 동일했고, 원본 순서로 초안 복원→취소→복원안 저장→새로고침과 연결 기록 재시작 복구를 확인했다.
- 실제 입력에서 영역 138개/유지 페이지 경계 137개를 표시했다(초기 영역 미확정·전체 페이지 유지 상태의 격리 DB). 모든 prov를 보존하고 자동 판단은 0개였다. 양쪽 화면·두 테마·1512/1024/375/320px, 대비·44px 터치·키보드 및 진단 표시를 검사했다. `qa/reading-light-1512.png`와 `qa/reading-light-375.png`를 시각 확인했다.
- 기존 4380 서버 PID 34092 유지. 기존 검수 API 전체가 작업 전과 동일(revision 47, 포함 122/제외 16, 역할 기록 0). 실제 DB의 기존 6개 테이블 스키마 동일, 신규 4단계 테이블 없음. 추천 상태 idle. 현재 `dist` 해시도 읽기 전용 비교로 동일함을 확인했다.
- 원본 JSON + PNG 167개(총 168파일)를 기준 커밋의 blob과 비교해 모두 동일함을 확인했다. 파일 삭제/원본 변경/추적 재추가/기준 이력 재작성은 하지 않았다. 테스트 기록·화면·빌드는 Git 제외 경로에만 있다.
- 독립 미리보기는 `http://127.0.0.1:4382`의 새 임시 DB와 `qa/stage4-dist`를 사용한다. 실제 사용자 4380 화면은 이전 빌드를 유지한다. 실제 모델 호출·원격 작업·5단계 전용 구현은 수행하지 않았다.

## 한정사항

- 사용자의 순서·연결 검수 기록을 제공하며 의미 판단의 정답, 자동 교정, 출력 사본의 공식 스키마/HTML 검증을 보장하지 않는다.
- 표·그림은 원자 요소이고 셀/그림 내부 순서 편집은 후속 범위다. 트리 진단의 영향은 관련 컨테이너/자손에 보수적으로 적용한다. 출처 없는 항목과 트리 오류의 누락 순서는 추정하지 않는다.
- 판단 불가는 사유/후속 확인을 갖춘 한계 기록으로 완료할 수 있고 의심은 완료를 막는다. 별도 영역 간 전체 배치 순서는 영역 판단과 원본 트리를 대조하며, 현재 편집은 같은 페이지·영역 안 순서와 페이지 경계 연결에 한정한다.
