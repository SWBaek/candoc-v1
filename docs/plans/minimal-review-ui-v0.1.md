# 최소 검수 web-ui v0.1 구현 범위

- 기준: 승인된 전체 검수 과정 사이드바 시안과 `docs/rules/document-review-v0.1.md`.
- 입력: `working-project/ieee-1547/raw/ieee1547-document.json`과 그 JSON에 연결된 전체 페이지 PNG. 원본은 읽기만 한다.
- 구현: 실제 페이지 목록·원문 확대, 포함·제외·보류 및 사유·근거 기록, 제외 취소, 현재 단계와 명시적인 단계 완료 기록.
- 추가 UI 조건: 일반 클릭·Ctrl/Cmd+클릭·체크박스는 해당 페이지의 선택만 켜거나 끄며 다른 페이지 선택을 유지한다. Shift+클릭은 기존 선택을 유지하면서 범위를 추가한다. 선택 페이지 일괄 제외, 기본으로 숨긴 상세 패널, 페이지 더블클릭 확대를 제공한다. 전체 페이지를 한 목록에서 스크롤로 확인하며 하단에서 썸네일 크기를 조절한다. 페이지 수 제한과 묶음 이동을 두지 않는다.
- 저장: 문서의 `inspection/review.sqlite`에 검수 상태만 저장한다. 입력 JSON과 규칙의 지문으로 검수 세션을 구분한다. 화면 이동과 검수 완료를 구분하며, 저장 전 초안은 적용·취소로 처리한다.
- 페이지 선별 완료: 제외할 페이지만 지정한 뒤 하단의 ‘나머지 유지하고 완료’로 남은 미검수 페이지를 포함 처리하고 단계 완료를 함께 저장한다. 기존 포함·제외 기록은 보존하고 보류 페이지가 있으면 완료를 제한한다. 나머지 페이지의 유지 결정은 원문 검사 근거와 구분해 기록한다. 방문만으로 단계 완료를 기록하지 않는다.
- 제외 표시: 기울어진 ‘제외됨’ 도장과 경계선으로 식별하고 해칭은 약하게 한다. 제외·보류·선택의 상태 표현을 구분하며, 선택에 여러 겹의 외곽선을 사용하지 않는다. 원문 확대와 선택 조작을 유지하고 제외를 취소하면 표시를 제거한다.
- 후속 단계: 이번에는 진행 상황과 검토 메모를 기록하는 화면을 제공한다. 제목·단락 편집, 교정 사본 출력, Docling 공식 스키마·HTML 검증, AI 연동은 후속 구현 범위다. 전체 검수 완료를 자동 판정하지 않는다.
- 완료 확인: 실제 JSON과 138개 페이지 이미지 표시, 저장 후 새로고침 및 서버 재시작 복구, 제외 후 복원, 입력 검증 및 충돌 방지, 원본 지문 유지, 데스크톱·좁은 화면 확인.
- 추가 확인: 일반 클릭의 독립 선택·해제 및 새로고침 복구, Shift 범위 밖의 기존 선택 유지, 여러 페이지 일괄 저장의 원자성, 36개를 넘는 Shift 범위 선택, 더블클릭 확대와 상세 패널 기본 숨김, 전체 138페이지 스크롤 접근, 썸네일 크기 조절 및 복구. 나머지 유지·완료의 원자성, 제외·보류 기록 보존, 수정 충돌, 제외 표시와 복원 및 재시작 복구를 확인한다. 기존 검수 기록을 보존한다.
- 시각 방향: 첨부된 메뉴 UI의 중립색, 얇은 경계선, 작은 메뉴와 여백을 적용한다. 반복 설명과 썸네일의 요소 수 표시는 줄이며, 전체 단계 목록과 완료·진행·대기 구분은 유지한다. 밝은·어두운 테마를 지원한다.
- 디자인 시스템 개선: 색상·글자 크기·간격·모서리·컨트롤 높이를 공통 토큰으로 정의하고 shadcn 컴포넌트에 적용한다. 보조 텍스트의 대비를 확보하며 검색·필터·상태 집계를 묶어 상단 공간을 줄인다. 데스크톱은 전체 단계 목록을 유지하고 모바일은 기본으로 접힌 검수 과정에서 전체 목록을 펼치고 단계를 이동할 수 있게 한다.
- 디자인 개선 확인: 밝은·어두운 테마의 텍스트 대비, 공통 컨트롤 크기, 첫 페이지의 화면 내 표시, 모바일 과정 목록 펼침·접기와 단계 이동, 제외·보류·선택 식별을 확인한다. 기존 기능과 원본·실제 검수 기록을 보존한다.

페이지 포함·제외 변경의 영향은 해당 페이지 및 인접 페이지로 기록한다. 이후 관련 검토가 완료된 경우 사용자가 영향 범위를 다시 확인하도록 알리고, 이를 확인하기 전에는 해당 결과가 유효하다고 표시하지 않는다.

## 문서 정보 통합

- 사용자 검수는 페이지 선별부터 시작한다. 대상·기본 무결성의 별도 완료 요구를 제거하고, 완료·메모 입력이 없는 ‘문서 정보’를 검수 목록 밖에 제공한다.
- 입력 시 JSON 읽기, DoclingDocument 식별, 화면에 필요한 페이지·요소 데이터만 확인한다. 문서명·원본 파일명·문서 스키마 버전·페이지와 요소 수·이미지 연결 상태를 표시한다. 변환 프로그램 버전은 JSON에 기록되어 있지 않으면 ‘알 수 없음’으로 표시한다.
- 현재 확인된 입력 스키마 버전은 1.10.0이다. 다른 버전은 확인되지 않은 버전이라고 안내하며, 화면에 필요한 데이터가 있으면 계속 사용할 수 있게 한다. 이미지 누락은 이미지 관련 기능의 제한으로 안내한다. 순환·소속·좌표 등 상세 진단과 자동 교정은 이번 범위에 포함하지 않는다.
- 기존 규칙의 0·1은 시스템 확인 범위로 두고 사용자 검수·진행률에는 2~12만 사용한다. 저장된 단계 ID, 규칙 파일과 세션 지문을 유지해 페이지 선별 완료·판단·사유·메모를 보존한다. 이전 0·1의 기록은 DB에 보존하되 사용자 단계로 노출하거나 최종 완료 조건에 포함하지 않는다.
- 완료 확인: 문서 정보에 완료 조작이 없음, 11개 사용자 검수 단계, 선별 완료의 진행률 반영, 변환 프로그램 버전 오표시 방지, 최소 입력 오류와 이미지 누락 안내, 이전 DB의 판단·완료·메모 보존, 최종 완료에서 0·1 제외. 타입·빌드·API·브라우저 검사와 실제 기록의 읽기 검증을 수행한다.
