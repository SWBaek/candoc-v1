# 프로젝트 공통 검수 Agent

기준 HEAD 0b36db0, 작업트리 깨끗함. 요청마다 새 ephemeral thread를 만드는 기존 추천 연결을 확장한다. 사용자 승인 범위는 프로젝트 공통 대화, 현재 화면/저장 영역 주석 연결, 필요 범위 조회, 반복 요소 변경안과 명시 저장이다. 다음 검수 단계 기능이나 교정 사본 생성은 추가하지 않는다.

## 구현

- 프로젝트/원본/규칙에 묶인 대화와 Codex thread ID를 SQLite에 별도로 보존한다. 요청은 기존 로그인/모델 카탈로그/프로젝트 설정을 재사용하며 같은 thread를 resume한다. 대화 저장은 검수 revision이나 완료를 변경하지 않는다. 실패/중단/재시작을 기록하고 자동 재요청/가짜 응답/조용한 thread 교체는 하지 않는다.
- 공통 우측 대화는 어느 단계에서도 열 수 있고 단계 이동 시 유지된다. 현재 단계/페이지/선택 항목 및 저장된 영역 주석을 명시 첨부한다. 원본 위치와 bbox는 참조/원본 페이지에 따라 대조하며 선택만으로 판단하지 않는다.
- host-owned dynamic tools로 페이지/텍스트 검색/영역/유사 위치/검수 기록을 제한된 페이지 크기로 조회한다. 조회한 실제 refs만 반복 머리말/꼬리말/번호 변경안에 쓸 수 있다. 모든 prov/orig/text/소속은 원본 그대로 유지하며 일부 조회의 전체 수/다음 offset/한계를 표시한다. 후보 추출은 자동 확정이 아니다.
- Agent는 검수 DB에 쓰지 않는다. 변경안의 대상/예외/근거/전후를 서버가 검증한다. UI의 승인 후 명시 저장만 기존 roleStore.saveBatch와 동일 트랜잭션/복원 경로를 사용한다. source/rule/revision/실제 대상 및 현재 소속 검증, 미저장 초안 보호를 적용한다.
- 기존 페이지/제목 추천 및 예전 영역 추천 이력은 호환 보존한다. 영역 주석의 주 경로를 공통 대화로 연결하고 이전 단발 추천은 보조 경로로 남긴다. 프로젝트 Agent의 실행 가능한 변경안은 이번에는 반복 요소 역할에 한정한다.

## 검증과 경계

원본/실제 DB/기존 dist 및 기존 서버를 보존하고 전후 읽기 전용 snapshot을 비교한다. 모든 테스트는 synthetic/copied 임시 DB, 자체 포트, 별도 CANDOC_BUILD_DIR=qa/project-agent-dist를 쓴다. 실제 모델 호출/원격 push/배포/새 외부 Agent/원본 수정은 하지 않는다. 원문 프롬프트 인젝션, 알 수 없는 도구/refs, 조회하지 않은 refs, 범위 밖/예외/원자 실패/충돌/취소/재시작 복구를 합성 프로토콜과 API로 확인한다. 실제 UI 대화 연속성/첨부/원문 이동/미저장 보호/승인 전후/다중 대상 및 모바일 focus/두 테마 캡처와 기존 전체 회귀, 타입, 격리 빌드를 수행한다. 단계별 로컬 커밋 후 결과와 실제 추론 미검증 한계를 보고한다.
