# 5단계 제목과 문서 개요 구현 계획

## 범위

- 기본 화면은 전체 제목 트리 하나다. 행 초점에서만 Tab/Shift+Tab으로 들여쓰기/내어쓰기를 수행하며 새 부모·하위 트리·수준을 함께 바꾼다. 검색 입력·체크박스·일반 버튼의 Tab은 native 포커스 이동이다. 개별 제목 카드 반복이나 텍스트 상자만으로 트리 편집을 대체하지 않는다.
- 검색 결과에는 상위 맥락을 유지한다. 행 초점·선택을 동기화하고 숨겨진 선택이 있으면 구조/일괄 편집을 막는다. 선택 수·예외·전체 적용 대상·하위항목 영향을 보여주는 최소 일괄 판단/수준 편집과 초안 실행취소, 명시적 원자 저장·직전 저장 복원을 제공한다.
- 기존 제목 라벨·3단계 제목 역할·절 번호 형태·짧은 텍스트를 후보 근거로 표시한다. 후보를 정답으로 취급하지 않는다. 전체 텍스트에서 후보 밖 항목도 찾아 검토하며 누락 원문을 추정해 만들지 않는다.
- 제목 여부를 먼저 명시적으로 판단하고 제목의 수준·절 번호·상위 제목·문서 구분을 기록한다. 반복 머리말·목록 후보와 원본 라벨/소속·orig/text·모든 prov·원문 위치를 대조한다. 번호 깊이로 수준/부모를 자동 확정하지 않는다.
- 저장된 제목 계층과 중복 문구/번호, 원본 순서 미확정·계층 충돌 진단을 보여준다. 유지 페이지 전체에서 표지·목차·서문·본문·부속서·참고문헌 등의 구분과 후보 누락/중복 확인을 별도로 기록한다.
- 기존 revision·명시적 저장·초안 취소·저장 값 복원·이동 확인·충돌 보존·원자성·재시작 복구를 재사용한다. 역할/소속·읽기 순서·페이지 범위·상위 제목 변경 시 관련 기록을 재검토한다. 제목 구조 변경은 관련 4단계 순서를 재검토하며 재확인 저장으로 의존 관계를 정리한다.
- 전체 후보와 유지 페이지 개요 확인, 페이지 선별·관련 영역/순서 확정, 미검수/재검토/의심 및 전체 범위 메모를 UI/API 완료 조건으로 확인한다. 근거/후속 확인이 있는 판단 불가는 한계 기록으로 남길 수 있다.

## 운영 경계와 제외

- 5단계만 구현한다. 6단계 전용 기능, 모델 호출, 외부 에이전트, 원격/push, 교정 사본 출력·공식 스키마/HTML 검증을 수행하지 않는다.
- 원본 JSON/PNG를 수정·삭제하지 않는다. 실제 4380 서버/DB/dist와 앞선 4382 미리보기는 제어하지 않는다. `qa/stage5-dist`, 임시 DB·동적 포트로 테스트하고 별도 빌드와 캡처를 제공한다. 기존 미리보기는 변경하지 않는다.
- 원본 파일·실제 DB 스키마/기록·idle 추천·기존 dist를 작업 전후 읽기 전용 비교한다. 소스/설정/계약/합성 테스트만 로컬 커밋한다.

## 검증

- API: 후보 밖 수동 추가, 라벨/번호가 자동 판단되지 않음, 모든 출처 보존, 제목 여부·수준/부모 순환·범위 밖·번호/문구 중복·누락 의심·페이지 구분, 의존 변경/복원·원자성·충돌·재시작·전체 완료 제한.
- 브라우저: 전체 트리의 Tab/Shift+Tab 부모·하위 트리·수준 변경, native Tab, 검색 상위맥락·초점/선택·숨겨진 선택 제한·예외와 영향 표시·일괄 편집·실행취소, 원문/JSON 대조·제목/비제목·계층 및 페이지 개요, 명시적 저장/초안 취소/저장 값 복원, 이동 확인·실패·새로고침·별도 자식 프로세스 재시작, 두 테마·1512/1024/375/320px·대비·44px 터치·키보드.
- 타입·격리 빌드·전체 API/브라우저 회귀, 스크린샷 시각 확인, 계약/DESIGN/README/최종 계획 갱신과 로컬 커밋 후 보고하고 대기한다.

## 최종 구현과 검증 결과

- `server/heading-review.mjs`의 후보/의존/개요·원자 저장/복원과 `heading-tree.mjs`의 제안 forest 검증을 전체 TOC UI에 연결했다. 임시 DB에만 `heading_reviews`, `outline_pages`, `heading_batches`를 추가했다. 4단계 연동은 실제 의미 변경과 동일 값 재확인을 구분한다.
- 기본 트리에서 제목 여부→부모/수준/번호 편집, 전체 하위 트리 Tab/Shift+Tab, Arrow 이동/접기/펼치기, 입력/버튼 native Tab을 구현했다. 검색의 상위 맥락, 초점/선택/편집 동기화, 숨겨진 선택/변경 보호, 선택 수/예외/하위 영향/명시 범위가 보이는 일괄 편집을 제공한다. 실행취소·초안 취소·저장 값 복원·직전 저장 복원·이동 보호와 후보 밖 수동 추가도 구현했다.
- 문서 구분/누락 확인은 구간/묶음과 예외·전체 텍스트 대조·사유·범위·명시적 저장 경로다. 같은 값도 전체 선택 페이지를 재확인 저장할 수 있다. 원본/제안 부모와 읽기 근거를 구분하며 PNG+bbox/JSON은 선택 항목에서 펼친다.
- 타입 검사와 `CANDOC_BUILD_DIR=qa/stage5-dist` 격리 빌드 통과. 최종 전체 `npm test` **43/43** 통과(기존 32개 + 제목 API 9개 + 트리 편집 2개). A/B 개별 확인→A 사유 보완→개요→5 완료, 부모 변경→4 동일 순서 확인→5 완료, 직접 후손만 재검토/메타데이터 유지, 원본 미확정 표시, 다중 prov/제외 복원, normal/error 불가능 트리, 구간 예외/일치·누락 coverage·12 제한, 실제 SQL 중간 실패 원자 롤백, revision/직전 복원 충돌을 확인했다. 의도한 DB 실패의 로그는 원자 실패 테스트 근거이며 테스트는 모두 통과했다.
- 최종 전체 `npm run test:browser` 회귀 통과. 기존 페이지 선별·AI 패널·3/4단계 워크플로 및 실제 입력 레이아웃을 함께 확인했다. 5단계는 Tab/Shift+Tab 하위 트리/부모/수준, Arrow·검색/접기 숨겨진 선택, native Tab, 일괄 예외·실행취소·초안 취소/저장 값·직전 저장 복원, PNG+bbox/charspan, 실 revision 충돌 초안 보존과 이동 보호, 구간 예외/동일 값 재확인·전체 완료, 후보 밖 비제목 저장/새로고침을 검사했다. 실제 별도 자식 프로세스 PID 변경 후 검수 상태 전체가 동일함을 확인했다.
- 실제 fixture의 전체 텍스트 2,937개/후보 2,493개/유지 페이지 138개 및 모든 prov를 확인했다. 초기 판단은 0개이며 미확정으로 표시한다. 전체 트리와 구간 모드·두 테마·1920/1512/1366/1024/375/320px의 가로 넘침, 주요 텍스트 대비 4.5 이상, 대표 컨트롤 44px 터치 영역을 검사했다. 주요 캡처 8개는 `web-ui/qa/headings-{tree|ranges}-{light|dark}-{1512|375}.png`에 남겼고 밝은 1512px 트리와 어두운 375px 트리를 직접 시각 확인했다.
- 기존 4380 PID **34092**, 4382 PID **8000** 유지. 4380 검수 API 전체와 실제 DB 기존 6개 테이블 스키마/모든 행이 작업 전과 동일(revision 47, 포함 122/제외 16, 역할 기록 0)했다. 실제 DB에 새 단계 스키마를 적용하지 않았다. 추천 상태 전체는 동일한 idle이며 기존 `dist`의 세 파일 SHA-256도 동일했다. 전후 읽기 전용 비교 근거는 Git 제외 경로 `web-ui/qa/stage5-preservation.json`에 있다.
- 원본 JSON + PNG 167개(총 168파일)를 `c83f2f5`의 blob과 비교해 모두 동일했다. 실제 파일 삭제/변경/추적 재추가와 기준 이력 재작성은 수행하지 않았다. baseline history에 입력이 남아 있다는 기존 사실은 유지된다.
- 독립 미리보기는 **http://127.0.0.1:4383**, 새 임시 DB `candoc-stage5-preview-321e6547e07f464e950b3a26d14be424/review.sqlite`, PID **25540**, `qa/stage5-dist`다. 5단계 화면만 열고 판단/완료는 저장하지 않았다. 4380과 4382는 기존 화면을 유지한다. 실제 모델 호출·원격/push·배포·새 외부 에이전트·6단계 전용 구현은 수행하지 않았다.

## 한정사항

- 후보는 넓은 휴리스틱이다. 짧은 본문도 후보가 될 수 있으며 전체 텍스트 보조 경로로 빠진 항목을 찾는다. 원문 대조와 의미 판단의 정답을 자동 검증하지 않는다.
- 4단계 영역 내 저장 순서가 신규 제목 초안과 순서 근거에 반영된다. 영역 사이 배치는 원본 슬롯을 사용한다. 기존 5단계 제안 계층은 자동 덮어쓰지 않으며 읽기 근거 변경 시 재검토한다. 다중 페이지 ref는 제목 행 하나와 모든 출처로 제공한다.
- 큰 일괄 요청은 기존 65,536바이트 제한을 유지하며 자동 부분 저장하지 않는다. 사용자가 명시적 범위를 나누어 저장한다. 실행취소는 메모리의 최근 30개 초안이며 브라우저 종료 후 초안 복구는 제공하지 않는다.
- 판단 불가는 사유/후속 확인을 갖춘 한계 기록으로 완료할 수 있고 의심은 완료를 막는다. 구간 확인은 사용자 기록이며 누락 텍스트를 생성하지 않는다. 교정 사본 적용·출력 및 공식 스키마/HTML 변환 검증은 수행하지 않았으며 6단계 작업은 별도 지시를 기다린다.
