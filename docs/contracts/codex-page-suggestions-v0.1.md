# Codex 페이지 선별 추천 계약 v0.1

작성일: 2026-10-06

## 목적과 판단 경계

표지·목차·감사문·참여자 명단·발행/이용 안내·뒤표지처럼 일반적으로 본문 검수에서 덜 필요한 페이지를 대략 선별한다. 정확한 요구사항 존재 여부를 판정하지 않는다. 서문·참고문헌도 내용이 해당 유형에 해당하면 후보로 제안할 수 있다. 기술 본문·정의·규범적 참조·기술 설명 부속서는 단순히 제목이나 `informative` 표시만으로 제외하지 않는다. JSON만으로 페이지 역할을 판단하기 어려우면 추천하지 않는다.

원본 페이지 번호(`prov.page_no`)를 사용한다. 추천은 사용자 판단과 구분하며, 추천 생성·조회·취소는 검수 revision·페이지 판단·단계 완료·SQLite를 변경하지 않는다. 사용자가 페이지를 선택하고 기존 일괄 제외 창에서 사유·근거를 확인해 저장해야 판단이 바뀐다.

## Codex 연결

- CanDoc Node 서버가 `codex app-server --listen stdio://`를 자식 프로세스로 실행한다. 별도 포트나 MCP 서버는 만들지 않는다.
- `CANDOC_CODEX_EXECUTABLE`로 실행 파일을 지정할 수 있다. Windows에서는 설치된 Codex Desktop의 `codex.exe`를 우선 사용한다. `.cmd` 파일은 직접 실행하지 않는다.
- 추천 요청마다 프로세스를 열고 종료한다. `initialize` 응답 후 `initialized`, `account/read`, `model/list`, `config/read`, `thread/start`, `turn/start` 순으로 처리한다.
- 로컬 Codex의 기존 인증을 사용한다. 로그인되지 않았으면 추천을 실패 처리하고 로그인 안내를 표시한다. 토큰·계정 이메일은 UI로 보내지 않는다.
- [프로젝트 설정](project-codex-settings-v0.1.md)의 모델·effort를 우선 사용한다. 최초 미설정은 기존 `CANDOC_CODEX_MODEL`/`model/list` 기본 모델을 사용한다. 목록에 없는 모델/지원하지 않는 effort는 거부한다. 실행 중 요청의 모델·effort는 설정 변경과 관계없이 유지한다.
- 스레드는 `sandbox: "read-only"`, `approvalPolicy: "never"`, `ephemeral: true`로 만든다. 앱·플러그인과 설정된 MCP 서버는 해당 스레드에서 비활성화한다. 문서 내용은 분석 자료이며, 문서에 포함된 명령은 수행하지 않는다. 서버가 클라이언트에 보내는 도구·승인 요청은 거부한다.
- 전체 페이지의 텍스트와 표 셀 내용, 요소 참조·라벨·그림 개수를 입력으로 전달한다. 원문 이미지 바이트·실제 검수 판단·검수 DB는 전달하지 않는다. 입력이 1 MiB를 넘으면 잘라 분석하지 않고 오류를 반환한다.
- `turn/start.outputSchema`로 아래 결과 형식을 요청한다. 최종 `agentMessage`의 `item/completed`와 성공 상태의 `turn/completed`를 모두 확인한다. 중간 답변이나 실패한 턴을 추천 완료로 취급하지 않는다.
- 공통 client는 UTF-8 작업별 한도와 별도로 Unicode 문자 1,048,576자 제한을 검사한다. 초과 요청은 원문을 자르지 않고 실행 전에 거부하며 RPC 오류는 method/안전한 입력 제한 정보만 표시한다.
- 전체 요청 제한 시간은 기본 240초다. `CANDOC_CODEX_TIMEOUT_MS`로 1초~10분 범위에서 지정할 수 있다. 취소·시간 초과·서버 종료 시 프로세스를 정리한다.

```json
{
  "suggestions": [
    { "pages": [7, 8, 9, 10], "reason": "감사문과 참여자·위원 명단" },
    { "pages": [13, 14, 15], "reason": "목차" }
  ]
}
```

백엔드는 알려진 원본 페이지 번호, 중복/겹침 없음, 비어 있지 않은 이유(500자 이하), 결과 객체의 정확한 필드 구성을 검증한다. 빈 `suggestions`는 정상 결과다. 예시 번호를 실제 문서의 정답으로 고정하지 않는다.

## HTTP API

경로: `/api/review/page-suggestions`. 기존 localhost·동일 출처·JSON 요청 제한을 적용한다.

| 메서드 | 요청 | 응답 |
| --- | --- | --- |
| GET | 없음 | 현재 추천 상태. 초기 상태는 `idle` |
| POST | `{}` | 추천 시작, HTTP 202. 실행 중 재요청은 409 |
| DELETE | `{ "id": "현재 요청 ID" }` | 실행 중 요청 취소. 다른 ID는 409 |

응답 필드: `id`, `status`(`idle/running/completed/failed/cancelled`), `sourceHash`, `ruleHash`, `suggestions`, `error`. 생성과 완료 시 입력 지문을 확인한다. 입력이나 규칙이 바뀌면 결과를 사용하지 않는다. 한 서버에서 추천 하나만 실행하며 서버 재시작 시 추천은 사라진다. 페이지 판단을 수정해도 같은 원본을 대상으로 한 추천은 유지된다.

## UI

페이지 선별 화면에 추천 요청 버튼, 진행/오류/빈 결과, 취소, 추천 그룹과 이유, 추천 페이지 선택 기능을 제공한다. 추천 페이지는 썸네일에서 ‘AI 추천’으로 표시하고 제외 도장과 구분한다. 그룹의 선택은 기존 페이지 선택에 추가하며 페이지 판단은 바꾸지 않는다. 전체 추천 선택은 검색·필터와 무관하며 전체 목록으로 돌아온다. 일부만 선택하려면 기존 클릭/체크박스로 해제한다.

요청과 응답은 우측 AI 패널에서 대화 형태로 표시한다. 기존 페이지 상세와 전환하며 추천 그룹에는 이유와 선택 버튼을 제공한다. ‘AI 응답’은 새 요청 없이 패널을 열고 닫는다. 닫아도 작업·조회는 계속된다. 표시 모드는 원본 지문별 브라우저 설정이며 검수 DB에 저장하지 않는다. 좁은 화면에서는 별도로 펼치고 추천 페이지 선택 후 갤러리로 돌아온다. 자유 입력·후속 턴·대화 저장은 현재 계약의 범위가 아니다. 배치·접근성은 [UI 디자인 계약](../../web-ui/DESIGN.md)을 따른다.

선택한 페이지가 모두 추천 후보인 경우 기존 일괄 제외 창의 사유에 해당 추천 이유를 채우고 근거를 `json`으로 설정한다. 사용자는 내용을 수정하거나 취소할 수 있다. 실제 제외 판단과 단계 완료의 조건은 기존 계약을 유지한다. 화면 새로고침은 서버 메모리의 추천을 복구하며, 브라우저를 닫아도 서버 작업은 계속된다.

## 검증과 한계

가짜 프로세스 검증은 프로토콜 처리 증거이며 모델 추론의 성공 증거가 아니다. 실제 Codex 생성은 임시 검수 DB에서 별도로 확인한다. 타입·빌드·API·브라우저 검사에서 원본 지문과 실제 검수 기록 보존을 확인한다. JSON 기반 추천은 이미지 대조나 정밀 검수의 완료를 뜻하지 않는다.

공식 프로토콜: [Codex App Server](https://developers.openai.com/codex/app-server). 설치 버전별 필드는 `codex app-server generate-json-schema --out <임시 폴더>`로 확인한다. 초기 구현 확인 버전은 0.160.1이다.
