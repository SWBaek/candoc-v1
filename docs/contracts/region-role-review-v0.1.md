# 3단계 반복 요소·영역·큰 역할·소속 계약 v0.1

작성일: 2026-10-06

## 범위와 원본 보존

첫 화면은 반복 머리말·꼬리말·페이지 번호 후보를 묶은 질문 검수다. 2026-10-07 질문 응답과 페이지별 확인 경로를 추가했다. 본문·각주·표·그림·소속의 개별 검토는 보조 경로다. 기존 라벨과 소속은 대조 자료이며 정답으로 가정하지 않는다. 판정은 검수 기록이며 DoclingDocument를 교정하거나 요소·출처를 삭제하지 않는다.

텍스트·표·그림·그룹을 컬렉션의 원본 JSON 경로로 식별한다. 원본 `self_ref`, 부모·자식, `orig/text`, `content_layer`, 표 셀과 모든 `prov`를 대조 근거로 제공한다. 다중 출처 요소의 판단은 해당 요소 전체에 적용되며 화면에 출처 페이지를 함께 표시한다. 그룹의 페이지는 자손 출처에서 유도했다고 표시하고, 페이지 정보가 없는 항목은 별도 경로로 검토한다. body/furniture 루트는 소속 선택 대상으로 제공한다.

좌표는 원본 TOPLEFT/BOTTOMLEFT와 페이지 크기로 비율 변환한다. 임의 반올림을 하지 않는다. 누락·범위 밖·0면적·지원하지 않는 원점은 위치를 추정하지 않고 표시 불가로 안내한다.

## 반복 후보와 예외

- 문구는 NFKC, 공백 통합, 소문자로 정규화한다. 유효한 위치가 페이지 상단 16% 또는 하단 18%에 있는 텍스트를 후보로 살핀다.
- 같은 문구·영역에서 세로 위치 차이 4%, 가로 중심 차이 8% 이내 출처를 묶는다. 서로 다른 원본 페이지에 두 번 이상 나타나야 후보 그룹이다.
- 숫자·로마 숫자와 `page`, `of`, `/` 번호 표현은 값이 달라도 같은 위치의 번호 패턴 후보로 묶는다. 단·복수 번호 체계의 정확성이나 인쇄 번호와 원본 페이지 번호의 일치는 자동 판정하지 않는다.
- 그룹마다 대표 사례, 전체 요소 수·범위 내 수·선택 수와 전체 원본 페이지 목록을 제공한다. 대표를 바꿔 원문과 JSON을 대조할 수 있다.
- 제외 페이지에만 출처가 있는 요소는 범위 밖이다. 여러 출처 중 유지 범위가 하나라도 있으면 요소는 검사 대상이다. 원본 모든 출처는 유지한다. 미검수·보류 페이지도 독립 검사는 가능하지만 단계 완료 전에는 페이지 선별을 확정해야 한다.
- 범위 밖 항목은 저장 대상에서 빼고, 개별 예외는 체크 해제로 일괄 저장에서 뺀다. 예외의 기존 기록은 바꾸지 않는다. 별도 판단은 개별 검토에서 저장한다.

후보 탐지는 휴리스틱이며 누락과 잘못 묶인 사례가 있을 수 있다. 대표 사례만으로 전체 그룹의 역할을 자동 확정하지 않는다. 선택한 대상 목록과 공통 사유를 확인한 사용자의 명시적 저장이 필요하다.

## 질문과 페이지 확인

`GET /api/role-questions`는 source/rule 지문, 질문 id/fingerprint, 전체 refs/pages/제안 역할, 대상별 open/apply/keep/defer/resolved 상태, 페이지별 refs/eligibleRefs와 출처 없는 refs를 제공한다. 반복 질문은 기존 정규화/위치 그룹을 재사용한다. 캡션 후보는 최대 350자이며 Figure/Fig./Table/그림/표 + 번호 + 구분자로 시작하고, 같은 페이지에서 가로가 겹치며 세로 간격이 페이지 높이 18% 이내인 표/그림이 있어야 한다. 반복 질문 대상은 캡션 질문에서 빼고 주소/기관명 등 짧은 텍스트만으로 질문을 만들지 않는다. 후보 탐지가 완전하다는 뜻은 아니다.

UI는 실제 bbox 주변을 CSS로 확대해 대표 첫/중간/끝 사례를 비교하며 전체 페이지와 모든 prov/charspan/원본 JSON도 확인할 수 있다. 여러 출처의 적용은 요소 전체이며 유지/제외 혼합 출처를 삭제하지 않는다. 원본/현재 검수 역할 → 제안, 대상 수/예외/범위 밖을 표시한다. 직접 수정은 기존 상세 양식과 저장 API를 유지한다.

`PUT /api/review/role-questions`: revision, sourceHash, ruleHash, questionId, fingerprint, 중복 없는 범위 내 refs, action(apply/keep/defer), reason. 선택/응답 초안은 기록을 바꾸지 않는다. apply 저장은 제안 영역/역할과 현재 검수 소속(없으면 원본 유지)을 대상별 검수 기록으로 저장하며 원본 사본 교정을 수행하지 않는다. 알려진 원본 큰 역할과 다르다고 사용자가 확인한 분류는 error, 같은 역할이나 머리말/꼬리말 안의 번호 세분화는 normal로 기록한다. 원본 라벨만의 발견이나 후보 표시로 오류를 확정하지 않는다. 근거는 json이며 이미지 표시만으로 이미지 대조를 주장하지 않는다. 상세 편집에서는 상태/근거를 직접 지정할 수 있다.

keep는 사유가 있는 제안 거절 기록이며 역할 기록/정상 coverage를 만들지 않는다. defer는 이유와 필요한 후속 확인을 같은 짧은 문장으로 받고 질문을 미해결로 남기며 3/12단계 완료를 제한한다. 질문 응답은 `role_question_answers`에 대상별로 보관한다. source/rule/question, 해당 역할 기록과 출처 페이지 범위 지문이 다르면 오래된 응답으로 표시한다. 현재 유효한 수동 역할 확인은 다른 역할을 선택했어도 질문을 해소하지만, 다른 질문에서 적용한 상충 역할은 자동 해소하지 않는다. 적용 후 직전 일괄 판단 복원은 역할 기록을 되돌리고 질문의 응답 지문도 다시 평가한다. 유지/보류 응답 자체는 역할 복원 버튼의 대상이 아니다.

`PUT /api/review/role-page-check`: revision, page, refs, checkedAll:true, evidence(json/both). 원문/JSON과 목록의 영역·역할·소속을 함께 확인한 사용자의 명시 저장이다. 유효한 기존 기록과 예외는 덮어쓰지 않는다. 기록이 없는 항목은 원본 라벨/큰 소속으로 보여준 역할을 normal로 확인하고, 알려진 기존 판단의 재검토는 같은 값과 기존 사유를 보존해 재확인한다. 미해결 질문/보류, 미확정 역할/영역, 출처 없음, 여러 유지 페이지에 걸친 항목은 간편 확인에서 빼고 직접 검토한다. 사용 가능한 이미지가 없으면 both를 거부한다. 전체 페이지를 확인했다고 선택 밖 항목까지 기록하지 않는다.

새 API는 기존 동일 출처/요청 제한/revision 트랜잭션을 사용한다. 적용/페이지 확인은 대상별 서로 다른 역할을 기존 role_batches에 이전/이후 기록으로 저장한다. 검증 또는 도중 쓰기 실패는 답변·판단·revision·복원 기록 모두 롤백한다. 실제 사용자 서버/DB는 배포하지 않고 보존했으며 새 테이블은 이번 격리 DB에서만 생성해 검증했다.

## 판단·저장·복원

### 영역 주석과 Agent 추천 (2026-10-07)

`GET /api/role-annotations`는 문서/규칙 지문, 원본 페이지·TOPLEFT 정규화 상자·코멘트·대응 refs/각 provIndex/겹침 비율의 주석 및 연결된 추천 작업을 반환한다. 주석은 역할 확인이 아니다. `PUT /api/review/role-annotations`는 revision/sourceHash/ruleHash/page/rect(left,top,width,height)/comment를 받아 이미지가 있는 유지 페이지의 실제 JSON 텍스트 bbox와 겹침이 있는 경우에만 새 주석을 저장한다. 부분 겹침도 표시하며 JSON에 없는 요소나 줄 단위 hbox를 추정하지 않는다. 기존 주석 수정 대신 새 주석으로 기록한다. 저장은 revision 트랜잭션을 사용하며 실패 시 주석/검수 버전 모두 보존한다.

`GET /api/role-models`는 기존 app-server의 모델/지원 effort 목록이다. `POST /api/review/role-annotation-suggestions`는 revision/sourceHash/ruleHash/annotationId/model/effort를 받아 202 작업을 시작한다. [프로젝트 설정](project-codex-settings-v0.1.md)이 있으면 model/effort는 생략 가능하며 저장값을 사용하고 다른 명시 값은 409로 거부한다. UI는 프로젝트 설정을 공유한다. 주석과 유지 페이지 JSON 텍스트·정규화 좌표·원본 bbox·all prov/charspan·orig/text·소속·현재 역할 기록으로 구조화된 추천을 요청한다. PNG는 Agent 입력에 포함하지 않는다. 같은 좌표 전체에 적용하거나 문구/출처를 합치거나 누락 내용을 복원하지 않는다. 머리말/꼬리말/페이지 번호의 독립 묶음만 제안하며 실제 ref·중복·유지 범위·유효 bbox·역할/영역을 서버에서 검증한다. 잘못된 응답은 failed로 남기고 역할 판단을 저장하지 않는다. 생성 시점의 source/rule/revision에 추천을 묶는다. `DELETE`는 현재 생성 중 id만 취소한다.

주석/요청 모델·effort/상태/근거/추천 전후는 `role_annotations`, `role_annotation_jobs`에 보존한다. 재시작 시 생성 중이던 작업은 failed와 재요청 안내로 남기며 완료 응답은 그대로 복구한다. 응답과 주석의 생성/조회/취소는 역할/완료 coverage를 만들지 않는다. 모델이 입력 밖 도구/권한을 요청하면 기존 연결이 거부한다. 연결 기반: [공식 Codex app-server 문서](https://learn.chatgpt.com/docs/app-server). 이번 구현은 기존 로그인·stdio·read-only/ephemeral·도구 비활성 설정을 재사용한다.

`PUT /api/review/role-annotation-apply`는 revision/sourceHash/ruleHash/id/groupId/exceptions를 받는다. 클라이언트가 새 역할이나 대상 refs를 주입할 수 없고 서버에 저장된 해당 추천에서 예외만 제외한다. 모든 버전·대상·예외를 검증한 뒤 기존 roleStore.saveBatch로 선택 대상별 기록을 원자적으로 저장한다. 현재 잠정 소속을 보존하고 알려진 원본 역할과의 차이는 사용자의 명시 확인 시에만 error, 같은 역할은 normal로 기록한다. 근거는 JSON이며 이미지 확인을 자동 기록하지 않는다. 다중 출처 판단은 해당 요소 전체에 적용하고 제외/유지 혼합 출처도 보존한다. 범위 밖/예외/무관한 기록은 바꾸지 않는다. 기존 일괄 판단 복원 API와 완료 제한을 유지한다. 한 묶음 저장 후 검수 버전이 바뀌므로 다른 이전 추천도 다시 요청해야 한다.

판단 필드: `status`(normal/error/suspected/unjudgeable), `region`, `role`, `parentRef`, `reason`, `evidence`(json/page_image/both), `followUp`. 영역·큰 역할·소속은 잠정 검수 판단이며 Docling 라벨 변경 명령이 아니다. 빈 `parentRef`는 각 대상의 원본 소속 유지다.

모든 판단에 사유가 필요하다. 정상은 영역·역할이 미확정이면 저장하지 않는다. 의심·판단 불가는 후속 확인이 필요하다. 사용할 원문 이미지가 없으면 이미지 근거를 허용하지 않는다. 없는 소속 대상·자기 참조·잠정 소속 순환은 거부한다.

| 경로 | 메서드·동작 |
| --- | --- |
| `/api/role-elements` | GET: 원본 지문, 전체 요소·소속 대상·반복 후보 그룹 |
| `/api/review/roles` | PUT: `revision`, `ref`와 판단 필드로 한 요소 저장 |

| `/api/review/role-groups` | PUT: `revision`, `action: restore`, `id`로 해당 일괄 저장 전 판단 복원 |

기존 localhost·동일 출처·JSON·65,536바이트 요청 제한을 재사용한다. 일괄 저장은 그룹·범위·판단을 검증하고 기존 revision 트랜잭션에서 대상별로 기록한다. 하나라도 실패하면 전체와 revision·복원 기록을 롤백한다.

직전 일괄 저장의 이전/이후 대상별 기록을 SQLite에 보관해 새로고침·서버 재시작 후에도 복원할 수 있다. 미검수였던 대상은 기록 없음으로, 기존 판단이 있던 대상은 이전 값으로 복원한다. 이후 대상 판단이 바뀌었거나 범위를 벗어나면 전체 복원을 거부한다. 복원은 단계 완료를 자동 복구하지 않는다.

`/api/review`는 기존 필드에 `roleReviews`, `roleCoverage`, `roleUndo`를 추가한다. 페이지 포함·제외·보류 변경은 관련 요소를 재검토로 표시한다. 판단 변경·복원은 이미 완료한 영역 및 후속 단계에 관련 페이지의 재검토 범위를 기록한다. 대기 단계는 완료된 것으로 만들지 않는다.

## 완료와 검증 경계

페이지 선별이 확정되고, 유지 범위 전체 요소의 미검수·재검토·의심과 보류 질문이 없어야 3단계 완료를 기록할 수 있다. 이유와 후속 확인이 있는 판단 불가는 결과로 남길 수 있다. 전체 범위·근거·미확인 사항 메모도 필요하다. UI와 API 모두 조건을 확인하며 최종 결과 단계도 영역 검수 범위를 확인한다.

테스트는 격리 DB와 합성 입력, 실제 로컬 fixture를 구분한다. 실제 문서의 레이아웃 확인은 의미적 판단의 정답 검증이 아니다. 실제 모델 호출·자동 AI 역할 판단·교정 사본 출력·공식 스키마/HTML 교정 완료 검증은 이번 구현 범위가 아니다.
