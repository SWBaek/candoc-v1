# 4단계 읽기 순서와 페이지 연결 계약 v0.1

작성일: 2026-10-06

## 범위와 원본

유지 페이지의 영역 안 읽기 순서와 인접 유지 페이지 사이의 연결을 사용자가 검수한다. 순서·연결안과 판단을 저장하며 원본 트리, 텍스트, 라벨, 소속, 모든 `prov`를 변경하지 않는다. 교정 사본 출력이나 공식 Docling 검증 완료를 의미하지 않는다. 5단계 전용 기능과 실제 모델 호출은 범위 밖이다.

텍스트·표·그림은 원본 컬렉션 경로로 식별한다. 표·그림은 한 요소로 다루며 셀 내부 순서는 후속 범위다. 그룹은 원본 트리 순회와 소속 근거에 사용한다. 각 `prov`를 `ref@provIndex`로 구분하고, 출처 없는 항목은 `ref@unlocated`로 제공한다. 알 수 없는 출처 페이지는 화면의 0번 범위로 표시하되 원본 `page_no`와 모든 출처 필드는 그대로 제공한다.

## 영역 순서와 트리 진단

페이지·잠정 영역별로 순서 대상을 묶는다. 서로 다른 단/소속의 요소도 같은 영역 안에서 함께 대조한다. 소속은 요소별 원본 및 3단계의 잠정 판단으로 확인하며 순서 이동으로 소속을 바꾸지 않는다. `body`와 `furniture`의 `children`을 순회한 순서를 대조 근거로 사용한다. 좌표/컬렉션 번호/페이지 번호로 빠진 순서를 추정하지 않는다.

트리 진단은 순환, 중복 참조와 첫 경로, 없는 참조, 루트에서 도달 불가를 제공한다. 순환·중복·없는 참조는 관련 컨테이너/자손의 순서에 영향을 준다고 보수적으로 표시하고, 도달 불가 항목에는 원본 순서 인덱스를 부여하지 않는다. 루트와 연결되지 않은 구성요소의 순환도 진단하되 순서를 생성하지 않는다. 영향이 없는 별도 구성요소의 원본 순서는 유지한다. 진단은 공식 스키마 또는 전체 무결성 검증을 대신하지 않는다.

`sourceOrderKnown=false`인 영역은 출처 목록으로 표시하고 정상 확정을 제한한다. 이때 `originalOrder`는 모든 출처를 열거한 표시 목록의 초기값이며 검증된 원본 읽기 순서가 아니다. UI도 ‘표시 목록으로 초안 되돌림’으로 구분한다. 진단 목록과 영향 대상은 범위 밖 문제를 포함해 제공한다.

순서안은 해당 영역의 모든 occurrence를 정확히 한 번씩 포함해야 한다. 누락·중복·범위 밖 ID는 거부한다. 위/아래 이동은 초안이며 저장 전까지 기록을 변경하지 않는다. 원본 순서로 초안 복원은 원본이나 기존 저장을 바꾸지 않는다. 초안 취소는 마지막 저장/선택 시점으로 돌아간다. 복원안을 기록하려면 별도로 저장한다. 정상은 원본 순서가 알려져 있고 원본 순서와 같은 안에만 허용한다. 다른 순서안은 오류 확인/의심/판단 불가로 기록한다. 출처 없는 항목의 순서를 정상·오류로 확정하지 않는다.

## 페이지 경계

제외 상태를 뺀 인접 유지 페이지의 경계를 모두 검수 대상으로 제공한다. 미검수·보류 페이지도 독립 검토는 가능하지만 완료 전에 선별을 확정해야 한다. 제외 간격은 원본 번호와 제외 목록으로 표시하고 연결을 자동 확정하지 않는다. 범위가 바뀌면 새 경계는 미검수이며 이전 경계 기록도 삭제하지 않는다.

경계 하나에 여러 문단/표/각주/기타 연결을 기록할 수 있다. `links`의 항목은 `from`, `to`, `kind`(paragraph/table/footnote/other), `relation`(continuation/separate/related/unknown)이다. 대상은 현재 경계의 양쪽 출처여야 한다. 동일 출처 쌍 중복, 반대편/범위 밖 대상은 거부한다. 연결이 없으면 `noConnection: true`로 명시한다. 연결 목록과 연결 없음은 동시에 저장할 수 없다. 판단 불가는 후속 확인을 기록하고 연결 목록을 비워 둘 수 있다.

정상·오류 확정에는 관련 3단계의 영역·역할·소속 확인이 필요하며 관계 미확정을 허용하지 않는다. 정상 이어짐은 같은 영역이어야 하고 표에는 양쪽 표, 문단에는 양쪽 텍스트, 각주에는 양쪽 각주 역할이 필요하다. 사람이 발견한 영역/유형 혼입은 오류 확인 또는 불확실한 판단으로 기록할 수 있다. 내용의 실제 이어짐은 사용자의 원문 대조 판단이며 자동 의미 검증하지 않는다.

## 저장·재검토·완료

공통 필드는 `status`(normal/error/suspected/unjudgeable), `reason`, `evidence`(json/page_image/both), `followUp`다. 모든 기록에 사유가 필요하고 의심·판단 불가에는 후속 확인이 필요하다. 사용할 페이지 이미지가 없으면 JSON 근거만 가능하다.

| 경로 | 동작 |
| --- | --- |
| `/api/reading-review` | GET: 입력/규칙 지문, 영역·경계·전체 요소·트리 진단 |
| `/api/review/reading-order` | PUT: `revision`, 영역 `id`, 공통 필드, `order` |
| `/api/review/page-connections` | PUT: `revision`, 경계 `id`, 공통 필드, `links`, `noConnection` |
| `/api/review` | GET: 순서/연결 기록, coverage, 재검토 상태 |
| `/api/review/stages/4` | PUT: 기존 단계 메모/완료/완료 취소 계약 |

기존 localhost·동일 출처·JSON·65,536바이트 제한과 revision 트랜잭션을 사용한다. 저장 대상과 모든 연결을 검증한 뒤 한 트랜잭션에 기록·revision·후속 단계 재검토를 저장한다. 실패하면 모두 롤백한다. 충돌 시 UI 초안을 보존하고 성공으로 표시하지 않는다. 새로고침/서버 프로세스 재시작 후 SQLite의 저장 기록을 복구한다. 초안은 메모리에만 보관한다.

3단계의 판단 상태·영역·역할·소속 또는 페이지 상태가 바뀌면 관련 순서/경계를 재검토한다. 판단의 설명 메모만 바뀐 경우 의미적 의존 지문은 유지한다. 역할 일괄 복원·제외 취소가 이전 값으로 돌아가더라도 읽기 순서 확인을 자동 복구하지 않는다. 분할/합쳐진 영역의 이전 기록은 보존하고 새 대상은 별도로 검수한다. 순서·연결 판단 저장은 완료된 4~12단계를 재검토로 표시하며 3단계 판단은 변경하지 않는다. 5단계 연동에서는 실제 순서/연결 또는 판단 의미 변경만 관련 제목/개요를 무효화한다. 동일 의미의 사유 보완과 재검토 해소 저장은 5단계 확인을 다시 무효화하지 않으며 제목→순서→제목 재확인 루프를 만들지 않는다. 상세 연동은 [5단계 계약](heading-review-v0.1.md)을 따른다.

4단계 완료는 전체 유지 범위의 순서·경계 기록, 페이지 선별 확정, 관련 영역 판단 확인, 미검수·재검토·의심 해소와 전체 범위 메모를 요구한다. 판단 불가는 사유/후속 확인을 갖춘 한계 기록으로 허용하며 문서 정확성이나 교정 완료를 뜻하지 않는다. 최종 12단계도 이 coverage를 다시 확인한다.

## 검증 환경

기존 사용자 4380 서버, 실제 DB와 `web-ui/dist`는 제어·변경하지 않는다. 빌드와 정적 파일은 `CANDOC_BUILD_DIR=qa/stage4-dist`로 분리하고 임시 DB·동적 포트에서 테스트한다. 테스트 자체가 만든 자식 프로세스만 재시작한다. 실제 fixture는 읽기 전용이며 입력/PNG를 Git에 다시 추가하지 않는다.
