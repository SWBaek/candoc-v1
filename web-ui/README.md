# CanDoc 최소 검수 UI v0.1

승인된 시안을 실제 IEEE-1547 DoclingDocument와 원문 PNG에 연결한 로컬 web-ui다. React와 shadcn/ui를 사용하며, 작은 Node HTTP API와 Node 내장 SQLite로 검수 기록을 저장한다.

UI를 추가·수정할 때는 [CanDoc UI 디자인 계약](DESIGN.md)을 따른다. 설계 원칙과 상태 의미는 계약에서, 실제 색상·크기·간격은 [공통 토큰](src/tokens.css)에서 관리한다.

## 실행

Node.js 24 이상이 필요하다. 이 환경에서는 Node 24.21.0으로 확인했다.

```powershell
cd C:\Projects\candoc-v1\web-ui
npm ci
npm run dev
```

브라우저에서 **http://127.0.0.1:4380**을 연다. 종료는 실행한 터미널에서 `Ctrl+C`를 누른다. 다시 실행하면 같은 DB의 기록을 복구한다. 빌드 이후에는 `npm start`로 실행할 수 있다. 이 PC에서 기존 4318 포트가 Windows 예약 범위에 포함되어 기본 포트를 4380으로 변경했다.

```powershell
npm start -- --port 4381
```

## 구현된 기능

- 중립색·얇은 경계선·통일된 아이콘을 사용하는 조용한 화면 구성. 필요한 설명은 검수 안내에서 펼쳐 보고, 밝은/어두운 테마 선택은 브라우저에 저장한다. 검색·필터·상태 집계는 하나의 도구 영역으로 묶는다.
- `src/tokens.css`에서 색상·글자 크기·간격·모서리·컨트롤 높이를 관리한다. 본문 14px, 조작 문구 13px, 보조 정보 12px을 사용하며 shadcn 버튼·입력·텍스트 영역·배지에 공통 규칙을 적용한다. 일반 컨트롤은 36px, 작은 버튼은 32px이며 터치 환경에서는 44px을 확보한다.
- JSON의 138개 원본 페이지와 연결된 PNG 읽기. 페이지 번호 검색·상태 필터·목록·이미지 확대·JSON 텍스트 대조.
- 일반 클릭·Ctrl/Cmd+클릭·체크박스로 해당 페이지의 선택만 켜거나 끈다. 다른 페이지 선택은 유지하며, Shift+클릭은 기존 선택에 연속 범위를 추가한다. 선택 페이지를 공통 사유로 일괄 제외하거나 일괄 포함해 제외를 취소한다. 여러 페이지의 판단을 하나의 SQLite 트랜잭션으로 저장한다.
- 우측 상세 패널은 기본으로 숨기며 필요할 때 연다. 페이지 더블클릭으로 해당 페이지를 선택하고 큰 원문 이미지를 연다.
- 전체 페이지를 한 목록에 표시해 스크롤만으로 끝까지 확인한다. 페이지 수 제한이나 묶음 이동을 두지 않는다. 하단 조절 바는 썸네일 크기를 조절하며, 크기를 바꿔도 전체 페이지는 유지한다. 가까운 이미지부터 불러오고 썸네일 크기·다중 선택·패널 표시 설정도 저장·복구한다.
- 페이지별 포함·제외·보류와 판단 사유·검토 메모·사용한 근거 저장. 초기 상태는 미검수이며, 제외 취소는 포함 선택 후 저장한다.
- 제외할 페이지만 지정한 뒤 하단의 ‘나머지 유지하고 완료’를 누르면 남은 미검수 페이지를 포함 처리하고 단계 완료를 함께 저장한다. 검색·필터나 선택 목록과 관계없이 문서 전체에 적용하며 기존 판단과 사유·메모를 보존한다. 나머지 유지 결정은 원문 이미지·JSON 검사 근거와 구분해 저장한다.
- 제외한 썸네일은 기울어진 ‘제외됨’ 도장과 색상 경계선으로 강조하고 해칭은 약하게 한다. 제외는 붉은색, 보류는 호박색, 선택은 외곽선과 체크로 구분한다. 원문 확대와 페이지 선택은 유지하며, 제외를 취소하면 표시가 사라진다.
- ‘문서 정보’는 완료가 필요 없는 별도 화면이다. 문서명·원본 파일명·문서 스키마 버전·페이지와 요소 수·이미지 연결 상태를 표시한다. 변환에 사용한 Docling 프로그램 버전이 기록되지 않은 경우 ‘알 수 없음’으로 표시한다. 현재 앱에서 표시를 확인한 입력 스키마 버전은 1.10.0이며, 다른 버전도 필요한 데이터가 있으면 안내 후 사용할 수 있다.
- 데스크톱은 페이지 선별부터 시작하는 전체 11단계 사이드바를 표시한다. 모바일은 ‘검수 과정 보기’에서 문서 정보와 전체 목록을 펼치며 단계 이동 후 다시 접는다. 완료는 초록색, 현재 단계는 굵게, 대기는 일반 글씨, 변경 영향이 있는 완료 결과는 재검토로 표시한다. 문서 정보는 진행률과 최종 완료 조건에 포함하지 않는다.
- 현재 단계·선택 페이지·상태 필터와 명시적으로 기록한 단계 완료·메모 저장. 화면 이동만으로 완료하지 않는다.
- 저장 전 초안의 적용·취소, 이동 시 초안 확인, 창 간 수정 충돌 검사. 보류 페이지가 남으면 페이지 선별 완료 기록을 제한한다. 나머지 유지와 완료가 실패하면 일부 페이지만 저장하지 않는다.
- 페이지 판단 변경 시 이미 완료된 관련 검토에 해당 페이지와 인접 페이지의 재검토 범위를 기록한다. 관련 요소 유형이 없는 단계는 유지한다.

3단계는 아래 **반복 요소·영역·큰 역할·소속 검수** 화면을 제공한다. 4단계는 아래 **읽기 순서와 페이지 연결** 화면을 제공한다. 5단계 이후는 **수동 검토 메모와 진행 기록**이며 제목·단락 전용 기능은 아직 없다. 페이지 선별에는 아래 Codex 제외 추천을 제공하며, 교정 사본 출력, 공식 Docling 스키마·HTML 변환 검증, 이후 단계의 AI 협업은 후속 범위다. 입력 시 JSON 읽기·DoclingDocument 식별·화면에 필요한 페이지 및 요소 데이터만 확인한다. 원문 이미지 누락은 관련 기능의 제한으로 안내하며 JSON 검수는 계속할 수 있다. 입력을 열 수 없는 경우에도 웹 화면에서 원인을 표시한다.

## 3단계 반복 요소·영역·큰 역할·소속

사이드바의 **영역·큰 역할·소속**을 열면 반복 머리말·꼬리말·페이지 번호 후보부터 묶음으로 확인한다. 문구 정규화·유사 위치·서로 다른 페이지 출현을 사용하며 페이지 번호는 숫자가 달라도 같은 위치의 번호 패턴으로 묶는다. 후보를 자동으로 확정하지 않는다.

대표 사례와 전체 대상·범위 내·선택 수, 원본 페이지 목록을 확인하고 예외는 체크를 해제한다. **선택한 요소의 공통 판단**에서 정상·오류 확인·의심·판단 불가, 잠정 영역·큰 역할·소속, 근거·사유·후속 확인을 입력해 명시적으로 일괄 저장한다. 제외 페이지에만 속한 항목은 저장하지 않으며 예외의 기존 판단도 유지한다. **판단 초안 취소**와 이동 시 저장·취소 확인을 지원한다. **직전 일괄 판단 복원**은 대상별 이전 판단으로 원자적으로 되돌리며 이후 개별 변경과 충돌하면 거부한다. 저장과 복원은 새로고침·서버 재시작 후에도 유지된다.

**개별 요소 검토**에서는 본문·각주·표·그림·구조 그룹의 역할과 소속을 확인한다. 이미지의 선택 위치와 원본 라벨·layer·부모·자식·orig/text·표 셀·모든 출처를 대조한다. 출처 없는 항목도 별도로 접근한다. 그룹의 페이지는 자손 출처에서 유도했다고 표시한다. 다중 출처 판단은 요소 전체에 적용된다. 위치가 없거나 유효하지 않으면 추정하지 않는다.

단계 완료는 페이지 선별 확정, 유지 범위 전체 요소의 미검수·재검토·의심 해소, 전체 범위·근거 메모가 필요하다. 판단 불가는 이유·후속 확인을 남길 수 있다. 페이지 범위 변경과 역할·소속 판단 변경은 관련 결과를 재검토로 표시한다. 기록은 원본을 수정하는 교정 명령이 아니며 실제 모델 호출과 AI 역할 자동 판정은 제공하지 않는다.

계약: [3단계 검수 계약](../docs/contracts/region-role-review-v0.1.md). 범위·검증 결과: [구현 계획](../docs/plans/region-role-review-v0.1.md).

## 4단계 읽기 순서와 페이지 연결

**영역 안 읽기 순서**에서 페이지·잠정 영역별 원본 트리와 순서안을 원문 이미지/JSON에 대조한다. 서로 다른 단/소속의 항목도 같은 영역 안에서 이동할 수 있다. 모든 출처를 유지하며 위/아래 이동, 원본 순서로 초안 복원, 저장과 취소를 제공한다. 순환·중복·없는 참조·도달 불가는 경로와 영향 대상으로 표시한다. 원본 순서가 미확정이면 표시 목록으로 구분하고 정상 확정을 제한한다.

**페이지 경계 연결**은 양쪽 유지 페이지를 함께 보여준다. 제외 간격은 원본 페이지 목록으로 표시한다. 문단·표·각주의 여러 연결 또는 명시적인 연결 없음 판단을 저장한다. 영역/역할/소속 확정 전에 독립적인 의심·판단 불가 기록은 가능하지만 정상·오류 확정과 단계 완료에는 관련 판단을 확인해야 한다.

탐색은 판단을 저장하지 않는다. 저장된 순서·연결은 새로고침과 프로세스 재시작 후 복구한다. 역할·소속 변경/복원과 페이지 범위 변경은 영향을 받는 순서·경계를 재검토로 표시한다. 전체 유지 범위의 미검수·재검토·의심, 페이지 선별 미확정과 전체 범위 메모를 완료 조건으로 확인한다. 원본 DoclingDocument 교정이나 공식 스키마/HTML 검증 완료를 뜻하지 않는다.

상세 API·진단·저장·완료 계약: [4단계 계약](../docs/contracts/reading-review-v0.1.md). 구현·검증 범위: [4단계 계획](../docs/plans/reading-review-v0.1.md).

## Codex 페이지 제외 추천

페이지 선별의 **AI 제외 추천** 버튼은 표지·목차·감사문·참여자 목록·발행 안내 등을 대략 선별한다. JSON 텍스트와 표 셀 내용을 Codex에 전달하며 원문 이미지는 전달하지 않는다. 정확한 요구사항 존재 여부를 판정하지 않는다.

요청과 추천 응답은 **우측 AI 검수 패널**에서 확인한다. 이유와 페이지 선택 버튼을 묶어 표시하며, 페이지 상세와 같은 공간을 전환해 사용한다. **AI 응답** 버튼은 새 요청 없이 패널만 열거나 닫는다. 닫아도 추천은 계속되며 다시 열어 확인할 수 있다. 표시 모드는 문서별로 브라우저에 저장한다. 데스크톱에서는 응답만 따로 스크롤하고 970px 이하에서는 별도 패널로 펼친다. 닫기·Escape·포커스 복귀를 지원한다. 현재는 한 번의 추천 요청·응답을 표시하며 자유 입력·후속 대화는 제공하지 않는다.

추천 이유를 확인하고 그룹 또는 전체를 선택한 뒤 기존 **제외** 버튼에서 사유·근거를 확인해 저장한다. 선택은 기존 선택에 추가되며 일부는 체크박스로 해제할 수 있다. 좁은 화면에서는 선택 후 패널을 닫아 갤러리로 돌아온다. 선택한 페이지가 모두 추천 후보이면 이유를 제외 사유에 채우고 근거를 JSON으로 설정한다. 추천 생성·취소 자체는 검수 판단과 단계 완료를 바꾸지 않는다. 진행 중에는 취소할 수 있다.

백엔드는 `codex app-server`를 stdio로 실행하며 로컬 Codex의 기존 로그인 상태를 사용한다. 초기 확인 버전은 0.160.1이다. Windows는 설치된 Codex Desktop 실행 파일을 우선 찾는다. 별도 MCP 서버와 추천 DB는 필요하지 않다. 추천 결과는 서버 메모리에만 보관하므로 새로고침으로 복구하지만 서버 재시작 시 사라진다. 저장한 판단은 기존 SQLite에 남는다.

필요하면 실행 전에 설정한다.

```powershell
$env:CANDOC_CODEX_EXECUTABLE = 'C:\Users\swBaek\AppData\Local\Programs\OpenAI\Codex\bin\codex.exe'
# 모델을 지정하지 않으면 model/list에서 기본 모델을 선택한다.
# $env:CANDOC_CODEX_MODEL = '<사용 가능한 모델 ID>'
# $env:CANDOC_CODEX_TIMEOUT_MS = '240000'
npm run dev
```

Codex가 로그인되지 않았으면 위 실행 파일로 `login`을 먼저 수행한다. 연결 실패·시간 초과·잘못된 추천 결과는 오류로 표시하고 판단을 저장하지 않는다. 입력이 1 MiB를 넘으면 일부를 잘라 추천하지 않고 처리 제한을 안내한다.

연결·HTTP·결과 형식: [Codex 페이지 선별 추천 계약 v0.1](../docs/contracts/codex-page-suggestions-v0.1.md). 구현 범위: [1차 구현 계획](../docs/plans/codex-page-suggestions-v0.1.md), [우측 패널 구현 계획](../docs/plans/ai-side-panel-v0.1.md).

입력 JSON과 PNG를 수정하거나 DB에 복제하지 않는다. 규칙에서 단계 이름을 읽고, 입력 JSON과 규칙의 SHA-256으로 검수 세션을 구분한다. 입력 또는 규칙이 바뀌면 이전 기록을 덮어쓰지 않고 새 세션을 연다. 실행 중 입력이 바뀌면 저장을 거부하며, 서버를 다시 시작해야 한다.

문서 정보 통합은 기존 규칙 파일과 저장된 단계 ID 2~12를 유지한다. 과거 0·1의 메모·완료 기록은 DB에 보존하지만 사용자 단계로 노출하거나 최종 완료 조건에 포함하지 않는다. 과거 기본 무결성 화면을 보고 있었다면 문서 정보로 연결한다. 기존 페이지 판단과 선별 완료는 그대로 복구한다.

SQLite의 보조 WAL 파일은 실행 중 생길 수 있다. DB를 파일 복사로 백업하려면 서버를 종료한 뒤 `review.sqlite`를 복사한다. 개발 테스트는 임시 DB를 사용하므로 실제 검수 기록에 테스트 판단을 넣지 않는다.

개발·검증 중 기존 사용자 서버를 임의로 중단하거나 재시작하지 않는다. 테스트 서버는 독립 임시 DB와 별도 포트를 사용하고 기존 사용자 기록은 읽기 전용으로 확인한다. 운영 경계는 [AGENTS.md](../AGENTS.md)에 기록했다.

원본 JSON·PNG·PDF는 Git 추적 대상이 아니다. 현재 로컬 fixture 경로와 저장소 외부 fixture 실행 방법은 [로컬 재현 입력](../docs/local-fixtures.md)에 정리했다. 다른 경로의 실제 문서로 회귀 검사하려면 동일 IEEE-1547 fixture 구조를 준비하고 다음 환경 변수를 설정한다. 테스트 검수 DB는 이 경로와 별도의 임시 디렉터리에 생성한다. 합성 3·4단계 API 검사는 실제 fixture 없이도 `node --test tests/roles.test.mjs tests/reading.test.mjs`로 실행할 수 있다.

```powershell
$env:CANDOC_FIXTURE_PROJECT = 'C:\CanDocFixtures\ieee-1547'
npm test
npm run test:browser
```

## 확인

기존 사용자 서버가 실행 중이면 정적 파일도 덮어쓰지 않는다. 테스트/미리보기 빌드는 별도 경로로 분리한다. 서버의 정적 파일 선택에도 같은 환경 변수를 사용한다. 브라우저 테스트는 기본 `qa/browser-dist`에서 자체 빌드하며, 아래 환경 변수를 지정하면 해당 격리 빌드를 사용한다. 테스트가 생성한 임시 DB/동적 포트/자식 프로세스만 재시작한다.

```powershell
$env:CANDOC_BUILD_DIR = 'qa/stage4-dist'
npm run build
npm run test:browser
# 독립 미리보기: 실제 DB 경로를 사용하지 않는다.
npm start -- --port 4382 --db "$env:TEMP\candoc-stage4-preview\review.sqlite"
```


```powershell
npm run typecheck
```

`npm test`는 기존 API 검사와 Codex 프로토콜·추천 API 검사를 실행한다. 가짜 App Server와 브라우저의 가짜 추천 결과는 모델 추론 검증과 구분한다. 브라우저 검사에는 추천 진행·새로고침·취소·실패·빈 결과, 추천 선택과 일부 해제, 사유·JSON 근거 확인, 명시적 저장·취소, 양쪽 테마와 모바일 검사가 포함된다. AI 패널의 열기·닫기·진행 중 복구·상세 전환·배치·키보드 포커스·터치 크기·대비도 확인한다.

실제 Codex 생성 검사는 별도로 실행한다. 기존 로그인과 사용량을 사용하며 임시 검수 DB에서 원본·검수 상태 보존을 확인한다. 개발 검증 결과는 `qa/codex-suggestions.json`에 남긴다.

```powershell
npm run test:codex
```

API 검사는 실제 전체 페이지 이미지, 사유 필수 조건, 저장·복구, 완료 조건, 관련 범위 재검토, 변경된 입력 세션 분리, 수정 충돌, 일괄 저장의 원자성 및 기존 DB의 검수 기록 보존을 확인한다. 나머지 유지·완료는 기존 판단 보존, 필터와 무관한 전체 적용, 보류·잘못된 요청 거부, 실패 시 원자성 및 재시작 복구를 확인한다. 브라우저 검사는 저장 → 새로고침 → 서버 재시작, 제외 취소, 초안 적용·취소, 단계 방문과 완료 분리, 일반 클릭·Shift/Ctrl/체크박스 선택·일괄 제외와 복원·더블클릭 확대·상세 기본 숨김·전체 138페이지 스크롤 접근·36개를 넘는 범위 선택·썸네일 크기 조절과 복구, 제외 표시·복원·선택 없이 나머지 유지·완료·보류 시 완료 제한을 확인한다. 화면 검사는 1512/1024/375/320px의 가로 넘침, 모바일 과정 목록의 키보드 펼침·접기와 단계 이동, 터치 환경의 44px 조작 영역, 밝은/어두운 테마의 주요 텍스트 4.5:1 이상 대비와 테마 선택 복구를 확인한다.

3단계 검사는 합성 입력에서 반복 문구·변하는 페이지 번호·예외·범위 밖 대상·모든 출처 보존·일괄 저장 원자성·이전 판단 복원·수정 충돌·완료 제한·재검토를 확인한다. 브라우저에서는 묶음 중심 조작, 출처 없는 항목·표의 개별 검토, 초안 취소·이동 확인, 저장·복원·새로고침·재시작을 확인한다. 실제 입력 3,110요소 레이아웃을 격리 DB에서 확인하며 모델 추론이나 판단 정답 검증과 구분한다.

4단계 검사는 다단 소속을 아우르는 정확한 순열, 다중 출처, 트리 진단과 정상 확정 제한, 다중 문단/표/각주 연결, 제외 간격, 원자성, 역할 복원 후 재검토와 완료 조건을 확인한다. 브라우저는 원본 초안 복원/취소/저장, 저장 후 새로고침 및 별도 자식 프로세스 재시작, 다중 연결/연결 없음, 이동 확인·충돌, 실제 입력의 양쪽 모드/테마·1512/1024/375/320px·대비·터치 영역을 확인한다. 모델 추론이나 의미 판단 정답 검증은 수행하지 않는다.

브라우저 테스트는 설치된 Playwright Chromium을 사용한다. 이 Windows 환경의 기존 캐시도 사용할 수 있다. 브라우저가 없으면 `npx playwright install chromium`을 실행하거나 `CANDOC_BROWSER_EXECUTABLE` 환경 변수로 테스트용 브라우저 경로를 지정한다.

문서 정보 통합 검사는 완료·메모 입력이 없는 화면과 11개 검수 단계, 스키마·변환 프로그램 버전 구분, 다른 버전·이미지 누락 안내, 긴 파일명의 모바일 줄바꿈, 입력 오류 화면을 확인한다. 이전 0·1의 기록과 페이지 판단·선별 완료 보존, 0·1을 제외한 최종 완료 조건 및 읽을 수 없는 입력에서 기존 DB 보존도 확인한다.
