# CanDoc UI 디자인 계약 v0.7

제정일: 2026-10-06

## 1. 적용 범위와 기준

이 문서는 CanDoc 검수 UI의 공통 설계 계약이다. 화면·컴포넌트·상태·조작을 추가하거나 수정할 때 먼저 읽고 따른다. 현재 화면뿐 아니라 이후 제목·단락·표 검수 화면과 AI 협업 UI에도 적용한다. 후속 기능의 구현 여부는 [README](README.md)에서 별도로 설명한다.

검수 절차와 판단 기준은 [문서 검사·교정 규칙](../docs/rules/document-review-v0.1.md)을 따른다. 원본 보존과 교정 결과 검증 조건은 [AGENTS.md](../AGENTS.md)를 따른다. 디자인 계약은 이 기준을 바꾸지 않는다.

| 기준 | 관리 위치 | 역할 |
| --- | --- | --- |
| 설계 원칙·상태 의미·확장 조건 | 이 문서 | 새 UI가 지켜야 할 계약 |
| 색상·글자 크기·간격·모서리·컨트롤 크기 | [src/tokens.css](src/tokens.css) | 실제 토큰 값의 기준 |
| 공통 스타일·레이아웃·반응형 동작 | [src/styles.css](src/styles.css) | 토큰을 화면에 적용 |
| 공통 조작 요소 | [src/components/ui](src/components/ui), [Icon](src/components/icon.tsx) | 재사용 가능한 구현 |
| 자동 검증 | [브라우저 검사](tests/browser.mjs), [API 검사](tests/api.test.mjs) | 확인 가능한 계약의 검사 |

토큰 값은 코드에서 관리하며 이 문서에 전체 수치를 복제하지 않는다. 코드가 계약과 다르면 원인을 확인하고 구현 또는 계약을 의도적으로 갱신한다. 기존 구현이라는 이유만으로 계약의 예외로 취급하지 않는다.

## 2. 시각 원칙

- 문서와 검수 대상이 화면의 중심이다. 상단 설명과 도구 영역이 원문·작업 공간을 과도하게 밀어내지 않도록 구성한다.
- 중립색 바탕, 얇은 경계선, 절제된 그림자를 사용한다. 색상과 강한 강조는 현재 작업·판단 상태·오류를 구분하는 데 사용한다.
- 제목·조작 문구·본문·보조 정보의 위계를 유지한다. 공간을 줄이기 위해 글자를 과도하게 작게 하거나 대비를 낮추지 않는다.
- 반복되는 설명은 안내 영역으로 묶는다. 판단에 필요한 근거, 저장 상태, 오류 사유는 해당 작업 가까이에 표시한다.
- 관련 도구는 묶고 반복되는 박스·배지·외곽선은 줄인다. 주요 행동이 함께 보이는 조작 영역에서는 현재 작업에 필요한 행동을 우선 강조한다.
- 밝은 테마와 어두운 테마를 함께 설계한다. 원문 이미지의 색상과 종이 배경은 출처 자료를 읽는 데 맞게 유지한다.

## 3. 토큰과 컴포넌트 사용

새 UI는 기존 의미에 맞는 토큰과 컴포넌트를 먼저 사용한다.

| 대상 | 사용 기준 |
| --- | --- |
| 화면 색상 | `--background`, `--canvas`, `--sidebar`, `--soft`, `--foreground`, `--muted`, `--border` |
| 상태·행동 색상 | `--primary`, `--current`, `--done`, `--warning`, `--excluded`, `--danger`와 해당 전경·배경 토큰 |
| 글자 | `--font-*`, `--weight-*`, `--line-*`를 역할에 맞게 사용 |
| 간격·모서리·경계·그림자 | `--space-*`, `--radius-*`, `--stroke*`, `--shadow-*` |
| 조작 요소·아이콘 | `--control-*`, `--icon-*`, 공통 `Icon` |

- 버튼·입력·텍스트 영역·배지는 [공통 shadcn 컴포넌트](src/components/ui)를 사용한다. 화면마다 별도의 기본 버튼 스타일을 만들지 않는다.
- `Button`의 기본 variant는 주요 행동, `outline`·`secondary`는 보조 행동, `ghost`는 탐색·부가 도구에 사용한다. `destructive`는 파괴적 행동을 표현한다. 검수 범위의 제외 상태와 오류·삭제의 의미를 혼용하지 않는다.
- 네이티브 select·checkbox·range 등도 사용할 수 있다. 공통 색상·크기·포커스·터치 기준을 적용한다. 새 shadcn 컴포넌트를 도입할 때도 기존 토큰에 맞춘다.
- 공통 아이콘의 선 스타일을 유지한다. 조작 아이콘에는 의미 있는 이름을 제공하고 장식용 아이콘은 보조 기술에서 숨긴다.
- 기존 토큰으로 표현할 수 없는 공통 역할은 의미가 드러나는 이름으로 추가하고, 색상 토큰은 두 테마를 함께 정의한다. 같은 역할의 토큰을 화면 이름별로 복제하지 않는다.
- 화면별 레이아웃, 원문 비율·좌표·확대 배율, 이미지 오버레이처럼 자료에 종속된 값은 별도로 정의할 수 있다. 공통 색상·글자·버튼 크기를 우회하기 위한 임의 값은 사용하지 않는다.

## 4. 상태의 의미와 표현

색상에 문구·기호·굵기·체크 등 다른 표시를 함께 사용한다. 단계 진행 상태, 페이지 판단, 현재 선택, 저장 상태를 서로 구분한다.

| 상태 | 의미 | 표현 계약 |
| --- | --- | --- |
| 단계 완료 | 검토 완료를 명시적으로 기록함 | 초록색 배경과 완료 기호 |
| 현재 단계 | 지금 보고 작업하는 위치 | 굵은 글씨와 현재 위치 표시; 완료·재검토 상태의 배경 유지 |
| 단계 대기 | 아직 완료하지 않은 단계 | 보조 색상과 일반 굵기; 비활성 조작으로 보이게 하지 않음 |
| 재검토 필요 | 기존 완료 판단에 영향을 주는 변경이 있음 | 경고 색상과 재검토 기호, 영향을 받은 범위 설명 |
| 페이지 미검수 | 포함·제외 등의 판단을 아직 기록하지 않음 | 중립 표현과 상태 이름 |
| 페이지 포함 | 검수 범위에 유지하기로 기록함 | 초록색 계열과 ‘포함’ 문구 |
| 페이지 제외 | 검수 범위에서 제외하기로 기록함 | 제외 색상, 경계선, 기울어진 ‘제외됨’ 도장; 해칭은 약하게 |
| 페이지 보류 | 판단을 확정하기 전에 확인이 필요함 | 경고 색상과 ‘보류’ 문구 |
| 선택 | 일괄 조작 등을 위한 대상 지정 | 외곽선과 체크; 판단 상태와 동시에 표시 |
| AI 제외 추천 | 에이전트가 제안한 제외 후보 | ‘AI 추천’ 문구와 이유; 페이지 제외·단계 완료와 구분 |
| 반복 요소 후보 | 문구·위치·출현으로 묶인 검사 대상 | 후보 문구, 전체·범위 내·선택 수와 원본 페이지; 오류 확정과 구분 |
| 요소 판단 | 정상·오류 확인·의심·판단 불가를 기록함 | 상태 이름과 사유·근거; 잠정 역할·소속과 원본을 구분 |
| 요소 재검토 | 페이지 범위 변경 등으로 다시 확인해야 함 | ‘재검토’ 문구, 대상 수와 관련 페이지 |
| 저장 전·저장 중·저장됨 | 초안 또는 기록의 저장 상태 | 해당 문구를 표시하고 저장 상태와 검토 완료를 구분 |
| 오류 | 행동이나 저장이 실패함 | 오류 색상과 원인·가능한 다음 행동 |

선택은 판단을 바꾸지 않는다. 제외 페이지도 선택하고 원문을 확대할 수 있으며, 제외를 취소하면 제외 표시를 제거한다. 겹치는 선택 테두리는 하나의 주된 외곽선으로 정리한다. 화면 방문이나 선택만으로 검수 완료를 표시하지 않는다.

## 5. 화면 구조와 반응형 동작

- 왼쪽 영역에 현재 문서명과 전체 검수 과정의 순서를 제공한다. 단계 이름과 순서는 검수 규칙을 기준으로 하며 화면마다 복제해 관리하지 않는다.
- 사용자 검수 목록은 페이지 선별부터 시작한다. 규칙의 대상·기본 무결성 확인은 시스템의 입력 확인 범위로 구분하고, 해당 두 항목의 완료를 사용자에게 요구하지 않는다. ‘문서 정보’는 검수 목록 밖에 제공하며 진행률·완료 조건에 포함하지 않는다.
- 문서 정보에는 JSON에서 확인할 수 있는 문서명·원본 파일명·문서 스키마 버전·페이지와 요소 수·이미지 연결 상태를 표시한다. 문서 스키마 버전을 Docling 프로그램 버전으로 표시하지 않는다. 기록되지 않은 정보는 ‘알 수 없음’으로 표시한다.
- 입력 확인은 파일 읽기·문서 식별·표시에 필요한 데이터에 한정한다. 다른 버전이나 이미지 누락은 사용 가능한 작업을 계속할 수 있도록 안내한다. 입력을 열 수 없는 경우에는 원인과 가능한 다음 행동을 표시한다. 상세 기술 진단을 필수 사용자 검수 단계로 추가하지 않는다.
- 데스크톱은 전체 단계 목록을 표시한다. 모바일은 기본으로 접힌 과정 목록을 펼칠 수 있게 하고, 단계 이동 후 접는다. 접힌 상태에서도 문서명과 현재 단계는 확인할 수 있어야 한다.
- 본문은 현재 작업의 제목·핵심 설명·도구·검수 대상으로 구성한다. 새 검수 유형의 내용 배치와 분할 화면은 작업 특성에 맞게 결정할 수 있다.
- 보조 상세 패널은 기본으로 숨기고 필요할 때 연다. 좁은 화면에서는 원문과 조작 요소가 읽을 수 있는 폭을 확보하도록 재배치한다.
- AI 응답과 페이지 상세는 같은 우측 공간을 전환해 사용한다. AI 응답은 데스크톱에서 독립 스크롤하며 결과가 길어져도 페이지 목록을 아래로 밀지 않는다. 970px 이하에서는 배경을 가린 별도 패널로 펼친다. 닫기·Escape와 포커스 복귀를 제공하며 좁은 화면에서는 패널 안에 키보드 포커스를 유지한다.
- 페이지 선별은 전체 페이지를 연속 스크롤로 접근하게 한다. 페이지 수 상한이나 묶음 이동을 추가하지 않는다. 검색·상태 필터는 사용할 수 있으며 결과 수와 전체 수를 구분한다.
- 썸네일 크기는 표시 밀도만 조절한다. 조절로 페이지가 누락되거나 선택·판단이 초기화되지 않도록 한다.
- 고정 도구 영역은 마지막 검수 대상과 조작 요소를 가리지 않도록 여백을 확보한다. 문서명·긴 문구·좁은 폭으로 전체 화면에 불필요한 가로 스크롤이 생기지 않도록 한다.
- 현재 화면의 열 수·픽셀 배치·스크린샷을 그대로 복제할 의무는 없다. 공통 위계와 상태 의미를 유지하면서 새 검수 작업에 맞게 확장한다.
- 3단계 첫 화면은 반복 머리말·꼬리말·페이지 번호 묶음 검수다. 대표 사례·전체 대상 수·원본 페이지 목록·예외 체크를 제공하고, 본문·각주·소속의 개별 검토는 보조 경로로 제공한다. 원문과 JSON 대조 옆에서 공통 판단을 편집하며 좁은 화면에서는 읽을 수 있는 폭으로 재배치한다.
- 4단계는 영역 안 순서안과 양쪽 유지 페이지의 연결안을 나누어 제공한다. 원문 위치·원본 소속·모든 출처와 순서안을 함께 대조하고, 서로 다른 단/소속도 같은 영역 안에서 검토한다. 제외 페이지 간격과 원본 트리 진단을 표시한다. 누락 순서를 추정하지 않으며 원본 순서 미확정 상태를 정상처럼 표시하지 않는다.

- 5단계 기본 화면은 전체 TOC 트리 하나이며 후보와 의심을 함께 표시한다. 제목 여부를 먼저 판단한 뒤 제안 부모·수준·절 번호를 편집한다. 원본 부모/소속과 4단계 읽기 근거를 구분하고 선택 항목의 PNG+bbox/JSON은 필요할 때 펼친다. 문서 구분·누락 확인은 전체 유지 페이지의 구간/묶음과 예외로 검토하며 개별 카드 반복으로 대체하지 않는다.

## 6. 조작과 저장 계약

- 일반 클릭·Ctrl/Cmd+클릭·체크박스는 해당 페이지의 선택만 켜거나 끈다. 다른 선택을 유지한다. Shift+클릭은 기존 선택에 연속 범위를 추가한다.
- 더블클릭으로 원문을 크게 볼 수 있게 한다. 터치와 키보드 사용자를 위해 확대 버튼 등 동등한 접근 경로도 제공한다.
- 일괄 행동에는 적용 대상과 페이지 수를 표시한다. 제외 판단에는 사유를 입력하고 명시적으로 저장하는 흐름을 유지한다.
- ‘나머지 유지하고 완료’는 문서 전체의 미검수 페이지를 포함 처리하고 페이지 선별 완료를 함께 기록한다. 검색·필터·선택에 한정하지 않으며 기존 판단·사유·메모를 보존한다. 보류가 남으면 완료를 제한한다.
- 판단·메모의 초안은 적용·저장 또는 취소로 처리한다. 이동 시 미저장 변경을 확인한다. 탐색과 선택이 판단이나 완료를 암묵적으로 확정하지 않도록 한다.
- 저장 실패나 수정 충돌을 성공처럼 표시하지 않는다. 일괄 저장 실패가 부분적인 판단 반영으로 남지 않도록 한다.
- AI 협업 UI는 제안·검토·적용 여부를 구분한다. 에이전트의 제안 표시와 실제 교정 적용·검증 완료가 같은 상태로 보이지 않도록 한다.
- 페이지 선별의 ‘AI 제외 추천’은 전체 원본 페이지의 JSON을 대상으로 표지·목차·참여자 목록 등을 대략 선별한다. 추천 버튼은 기존 도구 영역에 묶고 요청 시 우측 AI 응답 패널을 연다. 패널에서 요청·응답·진행·취소·오류·빈 결과를 표시하고 추천 묶음마다 이유와 페이지 선택을 제공한다. 자유 입력 대화가 구현되지 않은 상태에서 입력창을 제공하지 않는다.
- ‘AI 응답’은 새 추천을 실행하지 않고 패널만 열거나 닫는다. 닫아도 실행과 상태 조회는 계속되며 도구 영역에 진행 상태·추천 수를 표시한다. 패널 표시 모드는 원본 지문별로 브라우저에 저장하며 검수 기록은 바꾸지 않는다. 좁은 화면에서 추천 페이지를 선택하면 패널을 닫고 갤러리로 돌아온다.
- 추천 생성과 조회는 검수 기록을 변경하지 않는다. 추천 그룹 또는 전체 선택은 기존 선택에 추가하며, 검색·필터를 해제해 선택 대상을 확인할 수 있게 한다. 일부 페이지는 기존 선택 조작으로 해제한다. 추천을 적용하려면 기존 일괄 제외 창에서 사유·JSON 근거를 확인하고 명시적으로 저장한다.
- 추천 결과는 서버 실행 중에만 유지하며 새로고침으로 복구한다. 추천은 원문 대조·정밀 검수 완료를 뜻하지 않는다. 연결과 HTTP 계약은 [Codex 페이지 선별 추천 계약](../docs/contracts/codex-page-suggestions-v0.1.md)을 따른다.
- 반복 요소 후보는 자동 확정하지 않는다. 범위 밖 항목·체크 해제한 예외는 일괄 저장에서 제외하며 실제 선택 수·대상을 표시한다. 대표 선택·체크·초안은 판단을 저장하지 않는다. 저장·초안 취소·이동 시 확인과 직전 일괄 판단 복원을 제공한다. 복원이 후속 판단과 충돌하면 거부한다.
- 영역·역할·소속의 원본과 잠정 판단을 구분하고 모든 출처를 보존한다. 출처 없는 항목도 검토할 수 있으며 좌표나 역할을 추정해 채우지 않는다. 전체 유지 범위의 미검수·재검토·의심과 페이지 선별 미확정이 남으면 단계 완료를 제한한다. 상세 저장 계약은 [3단계 검수 계약](../docs/contracts/region-role-review-v0.1.md)을 따른다.
- 순서 이동·연결 선택은 초안이다. 명시적 저장·초안 취소와 원본 순서로 초안 복원을 제공하며 복원안도 별도 저장한다. 원본 순서가 미확정이면 표시 목록 되돌림으로 구분한다. 여러 문단/표/각주 연결 또는 명시적 연결 없음 판단을 저장하고, 관련 영역/소속·페이지 범위 변경과 역할 복원은 재검토를 요구한다. 전체 범위의 기록·한계와 완료 조건은 [4단계 검수 계약](../docs/contracts/reading-review-v0.1.md)을 따른다.

- 제목 행 초점의 Tab/Shift+Tab은 부모·하위 트리·수준·표시 순서를 함께 변경한다. 입력/체크박스/일반 버튼의 Tab은 native이며 Arrow로 제목 이동·접기/펼치기를 제공한다. 검색은 상위 맥락을 보존하고 초점·선택·편집 대상을 동기화한다. 숨겨진 선택/변경은 실수 편집·저장을 제한한다. 일괄 편집은 선택 수·예외·하위 영향·실제 저장 범위를 명시하고 실행취소·초안 취소·명시적 저장·저장 값/직전 저장 복원·미저장 이동 보호를 제공한다.
- 제목 의미/구조 변경은 직접 의존 후손·개요를 재검토하며 사유/근거 재확인은 다른 제목을 무효화하지 않는다. 정상과 오류 확인 모두 유효한 제안 트리를 요구한다. 전체 유지 후보/페이지 개요와 2/3/4 의존 확인을 완료 조건으로 적용한다. 상세 계약은 [5단계 계약](../docs/contracts/heading-review-v0.1.md)을 따른다.

## 7. 접근성과 확인 조건

- 일반 UI 텍스트는 `--font-caption`보다 작게 줄이지 않는다. 본문·조작 문구는 각 역할의 토큰을 사용한다. 원문 썸네일 속 글자는 확대 보기로 읽을 수 있게 한다.
- 일반 텍스트의 전경·배경 대비는 두 테마에서 최소 4.5:1을 확보한다. 비활성 상태의 조작 요소는 일반 텍스트와 구분해 점검한다.
- 터치 조작 영역은 최소 44 × 44px을 확보한다. 아이콘 자체 크기와 클릭 가능한 영역의 크기를 구분한다.
- 버튼·입력·선택·펼침 등은 키보드로 접근하고 조작할 수 있어야 한다. 포커스 표시와 조작 이름을 유지한다. 작은 화면에서 문구를 숨겨도 접근 가능한 이름은 제공한다.
- 새 UI는 빈 결과·긴 문구·선택·저장 중·비활성·오류 등 해당 기능에 필요한 상태를 확인한다. 밝은/어두운 테마와 데스크톱/모바일에서 작업 흐름을 확인한다.

현재 브라우저 검사는 1512/1024/375/320px 화면(5단계는 1366/1920px도 포함), 주요 텍스트의 대비, 공통 컨트롤 크기, 모바일 과정 펼침·접기·단계 이동, 터치 조작 영역과 기존 페이지 선별 흐름을 확인한다. 일부 요소를 검사하므로 새 UI의 계약 준수를 자동으로 보장하지 않는다. 새 요소에 필요한 검증을 추가하거나 직접 확인하고 그 범위를 기록한다.

UI 코드 변경 시 `web-ui`에서 타입 검사와 빌드를 수행하고, 변경한 동작에 관련된 브라우저 검사를 실행한다. 저장·판단 로직도 바뀌면 API 검사로 검증한다.

```powershell
npm run typecheck
npm run build
npm run test:browser
# 저장·판단 로직 변경 시
npm test
```

문서만 변경한 경우에는 링크·코드 경로·토큰 이름과 기존 계약의 정합성을 확인한다. 테스트와 미리보기는 실제 검수 기록을 변경하지 않는 방식으로 수행한다.

## 8. 확장과 계약 변경

새 UI를 추가할 때 기존 토큰·컴포넌트·상태 의미를 확인하고, 공통으로 필요한 역할만 확장한다. 화면별 배치와 작업 도구를 새로 구성하는 것은 허용한다. 계약을 바꾸어야 하는 경우에는 변경 이유와 영향을 받는 화면·상태를 설명하고 문서·코드·관련 검증을 함께 갱신한다.

토큰의 구체 값 조정은 코드에서 관리한다. 상태 의미·조작 원칙·필수 확인 조건 등 계약이 바뀌면 이 문서의 버전과 변경 기록을 갱신한다. 화면별 예외가 필요한 경우 이유·적용 범위·확인 방법을 명시하고 공통 스타일을 몰래 덮어쓰지 않는다.
